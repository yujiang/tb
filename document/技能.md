# 技能与 Buff 实现说明

按主题查阅和逐字段配置字典见 [tb 战斗知识库](wiki/index.md)；本页保留较完整的技能场景与实现说明。

本文整理近期完成的战斗能力，以当前源码和自动测试的实际行为为准。配置示例中的 ID 仅作示意；标为“配置片段”的对象需要补齐表的其他必填字段。

## 1. 技能、被动与 Buff 的职责

| 类型 | 当前落点 | 用途 |
| --- | --- | --- |
| 主动技能 | `SkillData`、`FightSkill`、`func` | 一次执行中的攻击、治疗、复活、加减 Buff、装配技能 |
| 被动技能 | `PassiveData`、`PassiveSkill.onInit` | 提供状态与属性、初始化自身 Buff、装配已有普攻/反击/协战技能 |
| 普通 Buff | `BuffData`、`FightBuff` | 属性、状态、周期效果、持续时间与事件次数 |
| 特殊 Buff | `BuffBuqu/Relife/Taunt/Reflect/Rest/Protect` | 需要介入选目标、受伤、死亡或行动检查的机制 |

技能的大部分差异由配置和 `func` 表达，特殊 Buff 则通过派生类接入对应生命周期。

当前技能函数为：

| `func` | 效果 |
| --- | --- |
| `normal`，或省略 | 走攻击技能管线；普通攻击也复用这套管线 |
| `heal` | 使用单位治疗属性执行治疗 |
| `poison` | 使用单位毒属性执行毒伤 |
| `relife` | 立即复活死亡目标，并恢复配置比例的生命 |
| `nohurt` | 执行加 Buff、驱散及装配技能，不造成攻击伤害 |

无伤害的加 Buff、驱散技能使用 `nohurt`，不要继续填写旧的 `addBuff/removeBuff` 函数名。未知函数名当前会回退到普通攻击流程。

## 2. 技能数值与目标

### 倍率和等级

| 字段 | 当前含义 | 省略值 |
| --- | --- | --- |
| `attackRate` | 先缩放当前来源属性的 `attack`，再加技能固定值及等级成长 | `1` |
| `damageRate` | 攻击伤害公式计算完毕、交给 `onHurt` 前的倍率 | `1` |
| `healRate` | 治疗公式结果倍率；复活技能中直接表示最大生命恢复比例 | `1` |
| `poisonRate` | 毒伤公式结果倍率 | `1` |

例如单位来源攻击为 100，技能 `attackRate=0.5`、固定 `attack=10`、每级 `attackLevel.attack=2`，3 级时合并攻击为 `100×0.5+10+2×3=66`。之后仍要经过目标防御等伤害公式，最后乘由 `damageRate`、相克和暴击加成相加得到的合并倍率。

`attackLevel/finalLevel` 使用固定加成加“每级加成 × 等级”，0 级仍保留固定加成。重复合并从原配置重算，不累计成长，不修改原表。

### 属性相克与相生

使用 `PropEnum`：`none=0`，之后依次为 `金、木、水、火、土`。单位的 `FightAttr.charProp`、`weaponProp` 默认均为 `none`，技能通过 `SkillData.skillProp` 覆盖本次属性。旧 `BaseAttack.property` 已删除，不参与属性合并或等级成长。

| 场景 | 施放方属性 | 目标属性 | 加成关系 |
| --- | --- | --- | --- |
| 普攻、物理或魔法攻击技能 | `skillProp`，未填才用自身 `weaponProp` | 目标 `charProp` | 相克给 `damageRate` 加 0.5 |
| 主动毒伤、周期毒伤 | 引用技能的 `skillProp`，未填才用施加者 `weaponProp` | 目标 `charProp` | 相克给 `poisonRate` 加 0.5 |
| 主动治疗、周期治疗 | `skillProp`，未填才用施加者 `charProp` | 目标 `charProp` | 相生给 `healRate` 加 0.5 |
| 主动复活、自动复活、吸血及伤害转移 | 沿用自身固定比例或已经结算的实际数值 | — | 不再次乘属性倍率 |

相克采用传统五行：**金克木、木克土、土克水、水克火、火克金**。相生为：**金生水、水生木、木生火、火生土、土生金**。均为单向关系，不做反方向减伤或同属性加成；任一方是 `none` 或属性未填，也不加成。关系函数返回命中时 1.5、其他情况 1；攻击、治疗和毒伤均取其减 1，与各自 rate 作加法合并。

显式 `skillProp: PropEnum.none` 表示技能无属性，不能用真假值判断后回退到武器或人物属性。只有未填才回退。

NPC 可改用两个独立弱点列表：`FightAttr.weakProp?: PropEnum[]` 与 `weakWeapon?: WeaponEnum[]`。五行弱点直接匹配本次攻击属性，兵器弱点直接匹配真实施放者的 `weapon`，命中任一项就给伤害或毒伤倍率加 0.5，多个命中不叠加，效果沿用 `克` 标记。配置任一列表后替代该 NPC 的受伤相克，不再叠加 `charProp`；空列表表示没有弱点，`none` 不参与匹配。两者都未配置时沿用人物相克，玩家与召唤物始终使用人物相克，治疗相生始终使用 `charProp`。

例如 `weakProp: [PropEnum.火]`、`weakWeapon: [WeaponEnum.刀]` 表示怕火或怕刀。普通攻击、攻击技能与主动/周期毒伤共用此判断，技能属性优先规则不变；技能显式无五行属性时，仍可匹配兵器弱点。旧的混合 `WeakPoint` 类型与 `weakPoint` 字段已替换，两个枚举的原数值保持不变。

```ts
// 单位基础属性
attr.weaponProp = PropEnum.金;
attr.charProp = PropEnum.水;

// SkillData 配置片段
{ skillProp: PropEnum.火 }  // 技能明确使用火属性
{ skillProp: PropEnum.none } // 本技能无属性，不使用武器或人物属性
```

攻击伤害先完成基础公式和免伤，再乘 `damageRate + (相克倍率 - 1) + 暴击加成`，最后交给受伤流程做防御姿态、保护分担、伤害修正与实际扣血。相克固定给伤害倍率加 0.5，例如没有暴击时 `(100 - 20免伤) × (0.4伤害倍率 + 0.5相克加成) = 72`。治疗乘 `healRate + (相生倍率 - 1) + 暴击加成`，毒伤乘 `poisonRate + (相克倍率 - 1)`；毒伤不执行暴击判定，主动和周期效果规则一致。rate 为 0 不屏蔽生克或暴击的额外加成；没有任何额外加成才仍为 0。实际治疗仍受生命上限约束；复活仍直接按最大生命比例恢复，不额外加属性或暴击加成。

暴击加成为 `0.5 + clamp(施放方 critDeep - 目标 critDeepAnit, 0, 1)`，仅本次暴击判定成功时加入，否则为 0；不再先把公式结果乘一次暴击倍率。暴击概率仍按原规则只判一次，保留 `crit` 标记。未配置暴击增伤时，基础伤害 100、damageRate 为 1，同时相克和暴击，结果为 `100 × (1 + 0.5 + 0.5) = 200`；damageRate 为 2 时则为 300。固定与比例免伤都在合并倍率之前处理，暴击加成不再放在免伤前。

连击、连招、追击、反击、协战与溅射各自读取本段技能属性及实际出手者属性。周期效果读取 Buff 施加者，不能拿共享上下文中的主攻者代替；协战者为水、主攻者为金时，协战照样可克火。属性判定不额外抽随机数。

命中相生关系时，当前治疗公式的 `effects` 加入 `"生"`；攻击或毒伤命中相克关系时加入 `"克"`，没有对应加成则不加。它们沿用原协议 `hurt/heal` 的第 7 项（下标 6），不增加字段，可与暴击共存，例如 `["crit", "克"]`。每次公式计算独立记录，连续周期效果及不同目标不串用标记，也不修改之前消息的效果数组；吸血与复活恢复不继承旧的生克标记。

简报伤害显示“150 点伤害（克）”或“200 点伤害（暴击、克）”，治疗显示“150 点生命（治疗，生）”，数字仍沿用原配色。MUD 的默认受伤、治疗描写也显示相应效果，专属文案仍按自己的模板输出。

攻击管线中的 `rand` 是发动概率，`0.2` 表示 20%；`0` 不发动，`1` 必定发动。它不代表命中率。物理攻击在发动后再检查命中，魔法攻击不走物理命中检查。需要稳定出手的主攻击技能通常填 `rand: 1`，概率子技能按玩法配置。其他 `func` 不统一经过这段攻击发动概率判定。

### 选目标

`sel` 指定阵营、死亡过滤、排序和副目标规则。`TargetSelectEnum.enmey` 是当前源码中的枚举拼写。

- `num` 是直接施放的总目标人数，省略为 `1`；`num > 1` 时直接选择一组目标，没有“主目标命中后再溅射”的前置步骤。`num: 99` 可以覆盖选定阵营全体，仍按 `die` 过滤，不包含另一阵营。
- `numSpread` 单独表示 `spread` 的副目标人数，不包含本次主目标，省略为 `1`；`shape` 仍表示以当前目标为中心的形状溅射。旧配置中用于副目标的 `num` 应迁移为 `numSpread`。
- 表现建议：只有单一主目标触发协战和保护，群攻与溅射均不触发。通过给群攻技能及溅射子技能填写 `nosupport: true, noprotect: true` 达成；这是填表建议，不是程序硬性规则。禁止字段省略或 `false` 不额外禁止，主技能及各子技能独立读取自己的配置。溅射保留单次攻击结算流程，不因此展开完整反应链。
- `initSkills` 会在整批注册后做中文告警检查：群攻/溅射禁止协战和保护、协战链禁止反击和反伤、协战根技能使用攻击类函数、大招禁止保护、主攻击 `rand: 1`、避免同时填写 `next/combo`。只告警，不修改配置或禁止注册。协战、大招等身份从技能表引用识别；未被引用为子技能/协战/反击的攻击类技能按主攻击建议检查。被动、怪物表及运行时装配的角色不在此检查范围。跨批次引用也能检查，不重复报告无关旧行，循环引用不会造成无限遍历。
- 例如敌方全体攻击使用 `sel: { target: TargetSelectEnum.enmey, num: 99 }`；友方三人治疗使用 `sel: { target: TargetSelectEnum.friend, num: 3, sortAttr: "hp" }`；单体加两人溅射使用 `sel: { target: TargetSelectEnum.enmey, numSpread: 2 }` 并配置 `spread` 子技能。
- 群体施放只支付一次费用、开始一次 CD、判定一次发动概率、添加一次 `afterSelfBuff`；每个目标独立命中和结算。同一次完整 action 结束后才处理自动复活、受伤轴的新攻击和胜负。群体选择不受嘲讽重定向，`self`、`duiwei` 仍受各自目标资格限制；`combo` 和协战依旧继承实际目标。

- `die` 省略时只选择存活单位；复活技能需配置 `DiedSelectEnum.die`。
- `sortAttr: "hp"` 默认按当前生命升序；`sortDescend: true` 为降序。选中低血量者不等于保证其一定缺血，全员满血时实际治疗仍可为 0。
- 显式非法目标会被拒绝，未指定目标才自动选择；单位 ID `0` 有效。
- 普攻可以手动指定死亡敌人守尸：执行时已复活则打原目标，仍死亡则跳过，不换人。
- 嘲讽在实际执行时覆盖符合条件的主目标；`combo` 后续段和协战继承实际目标，不重新选人。

## 3. 连击、连招、追击与溅射

| 字段 | 名称 | 目标规则 | 后续流程 |
| --- | --- | --- | --- |
| `next` | 连击 | 按子技能选择规则重新选主目标 | 配置子技能继续走攻击管线 |
| `combo` | 连招 | 固定继承上一段实际主目标 | 中间段不反击、不反伤，末段统一结算 |
| `kill` | 追击 | 原目标死亡后，按追击子技能规则选目标 | 配置子技能继续走攻击管线 |
| `spread` | 溅射 | 按当前攻击的副目标规则取得其他目标 | 对各副目标执行溅射子技能的单次攻击结算 |

`next` 与 `combo` 同时配置时，`next` 优先。没有 `inheritTarget` 字段。

配置子技能继承当前技能等级，但使用对应阶段的单位属性：`next/combo` 使用 `ft.next`，`kill` 使用 `ft.kill`，`spread` 使用 `ft.spread`。它们不一定与根技能的基础攻击相同。

配置的连击、连招、追击子技能可继续链接；普通攻击自带的概率连击、追击保留单次追加规则。每段发动概率只判一次。子技能不通过主动入口重复支付费用。

### 三连招与休息示例

以下是完整 `SkillData` 示例；休息 Buff 见后文。只有在各阶段来源攻击均为 100、目标防御等修正为 0 时，才对应 40、70、100 的实际伤害。

```ts
const common = {
    magic: true,
    rand: 1,
    attack: {},
    final: {},
    sel: { target: TargetSelectEnum.enmey },
};

initSkills([
    { ...common, id: 1001, name: "三连斩·一式", damageRate: 0.4,
      combo: 1002, cost: { mp: 10 }, afterSelfBuff: [[2001, 1, 1]] },
    { ...common, id: 1002, name: "三连斩·二式", damageRate: 0.7,
      combo: 1003 },
    { ...common, id: 1003, name: "三连斩·终式", damageRate: 1,
      nodback: false, nofback: false },
]);
```

连招的最终规则：

1. 始终攻击同一实际主目标，包括第一段被嘲讽重定向后的目标。
2. 中间段不触发普通反击、普通反伤，不因这两种反应打断动作。
3. 只有成功命中末段且双方在整条连招中未发生死亡，才按末段开关结算一次累计反伤，再尝试一次反击。
4. 累计值只包含本条连招对主目标实际扣掉的生命。追击、其他嵌套攻击及溅射不混入。
5. 实际伤害为 40、70、100，反伤比例为 20% 时，末段一次反伤 42；反伤致死则不再反击。
6. 后续段未发动、未命中、目标失效或任一方死亡时，不补结算累计反伤和反击。死亡后被其他机制立即复活，也视为连招已经打断。
7. 目标死亡时，仍可按该段 `kill` 配置走追击。吸血和命中后的 Buff 效果按段执行。

`afterSelfBuff` 是施放后给自己的 Buff：攻击类等待该段后续反应链返回后添加；已发动但未命中也添加；未发动不添加；施放者已死亡不添加。数组格式为 `[Buff ID, Buff 等级, 概率]`。其他技能函数通过主动入口成功返回后处理自身 Buff。

## 4. 吸血、反伤与反击

| 开关 | 含义 | 取值 |
| --- | --- | --- |
| `noblood` | 禁止本次攻击吸血 | 未禁止时读取技能合并后的 `final.bloodP` |
| `nodback` | 禁止本次攻击受到普通反伤 | 未禁止时读取目标对应伤害类型的 `final.dbackP` |
| `nofback` | 禁止本次攻击触发目标反击 | 未禁止时优先使用目标装配的反击技能 |
| `nosupport` | 禁止本次攻击召唤队友协战 | 未禁止时从合格队友中选一名尝试 |
| `noprotect` | 禁止目标由保护者分担本次伤害 | 每段技能独立读取 |

上述字段统一为禁止开关：**省略或 `false` 表示不禁止，只有 `true` 才禁止对应能力**。允许能力不代表必定发生，仍需满足吸血/反伤比例、反击与协战概率、保护 Buff 和目标状态等条件。普通攻击同样可协战、可被保护；反击专用类仍禁止继续触发目标反击，连招中间段等专用限制也保留。

旧字段 `blood/dback/fback/support/protect` 已移除。迁移旧表时，显式允许改为对应 `no...: false`（或省略），显式禁止改为 `no...: true`。旧表中原先依赖省略来关闭的能力，现在需要显式填禁止字段。协议反应标记、`fback` 属性分组和 `bloodP/dbackP` 比例字段不改名。

吸血和普通反伤以实际扣血为基数，当前攻击流程在实际伤害大于 1 时尝试。`bloodP=0.5`、实际扣血 50，则尝试恢复 25，最终受生命上限等规则约束。溢出伤害不计入吸血、反伤和伤害贡献。

反击装配：

```ts
a.addSkill(fbackId, level);
a.setFBackSkill(fbackId);
const equipped = a.getFBackSkill();
```

单位字段现名为 `fbackSkill`。反击使用反击者自己的 `ft.fback` 属性和已学技能等级，不额外支付主动技能费用。未装配有效技能时回退到普通物理反击；装配技能的发动概率失败时不再改用普通反击。禁止 `attack` 的单位不能反击。

### 当前普通攻击技能的实际顺序

```text
发动、物理命中判定
→ 扣血（含保护分担、受伤与死亡处理）
→ 命中后的 Buff 增删、技能装配
→ 吸血、普通反伤（连招反伤延至末段）
→ 目标存活且配置允许时尝试协战
→ 溅射
→ 连招末段满足条件时结算累计反伤
→ 目标死亡：尝试 kill 追击
  目标存活：符合条件时先尝试反击，反击未成功才执行 next/combo
→ 施放后自身 Buff
→ 最外层行动结束，处理延迟效果，再判断胜负
```

各步骤都受单位是否死亡等条件约束。当前代码并非固定“先 next 再反击”；普通分支成功反击会跳过原攻击这一层的 `next`。连招中间段则跳过反击检查，继续下一段。

## 5. 协战 support

A、B 同阵营，A 已装配协战技能；B 的攻击技能没有设置 `nosupport: true`。B 成功命中 C 后，若 C 仍存活且 B 未死亡，在 B 的 `next` 等后续流程之前，由 A 尝试攻击同一个 C。

```ts
a.addSkill(supportId, level);
a.setSupportSkill(supportId);
// B 的主攻击技能配置片段
{ nosupport: false }
```

候选先过滤，再随机选择：

- 排除 B 自己、其他阵营、死亡或离场单位。
- 排除 `isForbid("attack")` 的单位及存在休息等阻止行动 Buff 的单位。
- 必须装配可查询到的攻击类技能，`func` 为 `normal` 或省略。
- 本全局回合已经尝试过协战的单位不能再次入选。

只有一人时直接选择，不消耗选人随机数；多人时等概率随机选一人，再由攻击管线判定一次该技能的 `rand`。失败不转选其他人。**选中并尝试就消耗本回合机会，rand 失败、未命中均不返还。**

次数按单位、按全局回合记录，死亡复活、改装和额外输入次数不会重置。候选因禁止攻击等原因被排除，不消耗机会；解除后本回合仍可入选。

协战继承实际主目标，不重新排序、不被新嘲讽改向。主攻击杀 C 时没有协战，也不消耗协战机会，原攻击走自己的 `kill`。协战过程中击杀 C，则后续按死亡状态继续结算。

协战读取 A 自己的基础物理/魔法属性及已学技能等级，复用倍率、连击、连招、吸血、反伤、反击等攻击机制，不额外收费。协战及其整条后续反应链不再召唤其他协战者。返回 B 原有流程后继续按原规则执行。

为保持协战表现简洁，**协战技能推荐配置 `nofback: true`、`nodback: true`，不触发目标反击，也不受到普通反伤**。这里必须显式填写禁止，省略表示允许。无需修改协战程序逻辑。若协战技能还链接 `next/combo/kill/spread` 子技能，应逐个检查这些子技能的相应配置，避免后续段又引出反击、反伤；主攻击技能的开关按自身玩法单独配置。

```ts
// 协战 SkillData 配置片段
{ nofback: true, nodback: true }
```

这里的 `nodback` 禁止普通比例反伤，不控制 `BuffReflect` 的伤害反射；反射仍按自身 Buff 规则处理。

连招中间不插入协战，末段未设置 `nosupport: true` 时才尝试。表现消息标记仍为 `support`，简报显示 `【协战】`。

`FightReport` 在完整消息批次内可前瞻确认实际发生的协战，把主攻与协战的出手描述合成一行“同时攻击”；双方伤害仍按原结算顺序显示。未发动不会虚构协战，已发动但未命中保留同时出手描述，并在原位置显示未命中结果。拆批、跨行动边界或关联不明时不合并，客户端状态仍逐条更新，不提前扣血。`FightMud` 保持自身逐消息描写。

查看保护与协战组合简报：

```sh
npm run test:build
node --test .test-build/tests/report/test_report_protect_support.js
```

该测试运行实际战斗：低速铁卫先保护少侠，剑客与侠客同时出手，铁卫和少侠分担伤害；拳师随后再攻击，同回合不再协战，铁卫分担致死后才显示死亡。每批消息都检查客户端与服务器一致性。

## 6. 不屈

配置片段：

```ts
{ class: "buqu", prior: 1000 }
```

固定监听 `beforeHurt`，默认优先级 1000。只有伤害最终会致死时，将本次伤害限制为“当前生命 − 1”，随后消耗并移除 Buff。不是回血或复活，不会发生真实死亡，也不清死亡 Buff。

- 每个单位在同一个 `Fight` 中只成功触发一次，重加、替换或复活不刷新；新战斗重新获得机会。
- 非致命伤害不消耗机会；1 血时可以把致命伤害改为 0。
- 已有 `minHp > 0` 锁血时不消耗不屈。
- 可以用于保护者的分担伤害；分担不触发普通受伤回调，但仍经过必要的伤害修正。
- 与自动复活同时存在时，先由不屈拦截一次；之后真正死亡才会触发自动复活，两者分别计次。

其他减伤监听应排在不屈之前；`prior` 越小越先执行，同优先级按注册顺序。

## 7. 自动复活与主动复活

### 自动复活 Buff

```ts
// 配置片段
{ class: "relife", classParam: 0.3, dieNotRemove: true }
```

固定监听 `die`，默认优先级 1000。`classParam` 是自身最大生命的恢复比例，省略为 0.2，范围 `(0, 1]`；恢复量向下取整，至少 1 血。

触发顺序：

```text
真实死亡 → 清除普通死亡可移除 Buff → 登记待复活效果
→ 本次完整行动及反应链全部结束
→ 检查复活资格 → 消耗并移除自动复活 Buff → relife → heal
→ 判断胜负
```

必须设置 `dieNotRemove: true`，否则 Buff 在死亡清理时就被移除，无法收到死亡事件。

每个单位每场只成功触发一次。`禁复活` 会阻止复活且不消耗成功机会；等待期间已被其他效果复活、原 Buff 被驱散或替换、单位离场时，待处理效果失效。不是等全回合结束；完成这次行动的复活后，其他单位照常行动。

三连击第二段致死时，单位在当前反应链中保持死亡，不会立即站起再被第三段打死。双方最后单位同时死亡时，先处理所有待复活效果，随后再判断胜负。

### 主动复活技能

```ts
// SkillData 配置片段
{
    func: "relife",
    healRate: 0.3,
    sel: { target: TargetSelectEnum.friend, die: DiedSelectEnum.die },
}
```

恢复 `floor(目标最大生命 × healRate)`，上限为最大生命；省略倍率时满血。结果不足 1 血、目标不是死亡状态或存在 `禁复活` 时不复活。不再使用 `attack.attack` 表示复活比例。

主动复活执行时立即生效；自动复活 Buff 才延迟到行动结束。两者恢复生命都带复活标记，不会被治疗反射转移走。

## 8. 嘲讽

配置 `class: "taunt"`，Buff 挂在**被嘲讽者**身上，施加者是被强制攻击的目标。

例如 A 嘲讽 B：`b.addBuff(a, ..., tauntId, level, ctx)`。B 施展敌方目标技能或普通攻击时，主目标改为 A；不会因此禁止 B 行动，也不改变 B 原来提交的指令对象。

对自己、友方的技能不受此重定向影响。嘲讽者必须仍在战斗中、存活，并符合技能目标资格。失效的嘲讽不会强制攻击非法目标。副目标按原规则选择；连招后续段和协战沿用已经确定的目标。

## 9. 反射

```ts
// 配置片段
{ class: "reflect", classParam: { magicOnly: true } }
```

固定监听 `beforeHurt/beforeHeal`，默认优先级 0。`magicOnly` 省略为 `true`；设为 `false` 时也反射物理伤害。

### 伤害反射

取消自己这次伤害，将进入监听时的伤害交给原攻击者受伤，不先按反射者剩余生命截断，也不重新施放或计算一遍技能。接收者仍经过自己的防御、伤害修正、不屈、死亡及自动复活流程。

反射与普通 `dback` 反伤不同：反射者不承受被转移的原伤害；普通反伤是在目标实际扣血后按比例再扣攻击者生命。原攻击被反射取消时，实际扣血为 0，不据此产生原攻击者的吸血或普通反伤。

已反射的伤害不再次反射。保护分担的 `share` 伤害也不反射。攻击者已死亡、离场或就是自己时，不转移，保留原受伤。

### 治疗转移

自己受到普通治疗时，将治疗量转给随机一个存活敌人，该敌人获得治疗，归因于反射者。转移发生在自身满血截断之前；接收者仍受生命上限和禁疗约束，不再次转移。

无存活敌人时保留原治疗。`magicOnly` 不限制治疗转移。复活恢复生命不参与转移，避免站起来后仍为 0 血。

正数 `times` 按实际转移事件消耗，用完移除；未发生转移不扣。持续时间、死亡保留和驱散仍由通用字段控制。

## 10. 保护

A 保护 B，A、B 必须是同阵营不同的存活单位。

```ts
// FightData 配置：protectBuff 指向 class: "protect" 的 Buff
fight.processUnit(a, { cmd: FightCmdEnum.protect, target: b.uid });

// 保护 Buff 配置片段
{ class: "protect", turnType: BuffTurnEnum.afterTurn, lastTurn: 1 }
```

保护指令占用 A 本次行动。`FightLoopWest` 收齐指令后将保护指令按更高优先级排序，同优先级按速度；仍在统一行动队列中，先发送行动条，再按队列执行。宿主直接调用 `processUnit` 时自行安排顺序。

Buff 挂在 B 身上，施加者为 A；固定监听 `beforeHurt`，默认优先级 500。B 受到直接攻击伤害时，A 分担 `floor(伤害 / 2)`，余数留给 B。分担发生在 B 剩余生命截断之前；A 不足以承担的部分不转回 B。

**技能默认可以被保护，只有 `noprotect: true` 时禁止分担。** 普通攻击保留可被保护的行为；大招显式填写 `noprotect: true`，由 B 自己承受全部伤害，不消耗或移除身上的保护 Buff。

```ts
// SkillData 配置片段
{ name: "普通招式", noprotect: false }  // 允许分担
{ name: "大招", noprotect: true }    // 禁止分担；普通招式可省略该字段
```

连击、连招、追击、溅射、反击与协战技能均读取各自的 `noprotect`，不继承主攻或前一段的开关。主动 `poison` 也传递这个开关；周期 Buff 伤害仍由来源过滤排除，即使引用技能未禁止保护也不会分担。底层直接调用 `onHurt` 时，可用 `HurtOptions.noprotect: true` 禁止分担；省略则允许，技能入口会明确传入配置结果。

- 只分担来源 `skill` 的伤害，包含普攻；排除周期 Buff、普通反伤、反射和分担伤害。
- 同次伤害最多一个保护效果，互相保护不递归。
- A 死亡、离场或阵营不再相同时不分担。
- A 保留防御、伤害修正、不屈、死亡清理及延迟自动复活。
- **A 的分担不触发反射或普通 `hurt` 事件，不展开 A 的反击、反伤等受伤反应。**
- 后续吸血、B 的反伤和连招累计，只使用 B 自身实际扣血，不加上 A 的损失。

例如伤害 100，双方各扣 50；攻击者吸血 50% 得 25，B 的反伤 20% 为 10。

双方先完成扣血并连续发送两条受伤消息，再处理普通受伤回调和死亡。宿主可按保护触发中的双方 ID，将伤害表现作为同一次命中同时播放；即使 A 分担致死，死亡表现也不会插在双方伤害消息之间。tb 本身不负责动画。

`FightReport` 将同批内相邻、同一攻击者的 `share` 与主目标伤害合为一句，例如“剑客 对 铁卫 造成 50 点分担伤害，剩余生命 30；对 少侠 造成 50 点伤害，剩余生命 950”。双方客户端状态仍逐条更新，完成后才输出该句；两处数字分别保留伤害或暴击配色，仅行首人名上阵营色。拆批或伤害不匹配时保留两行，`FightMud` 保持原有描写。

保护通常设置 `afterTurn + lastTurn: 1`，在本回合结束移除，不需要特殊到期代码。

## 11. 休息

配置 `class: "rest"`。只要持有休息 Buff，`Fight.processUnit` 的行动检查就跳过主动行动，并发送 `skipAction`；协战候选也会排除该单位。休息本身没有固定的持续时长，由通用计时字段决定。

三连招后强制休息下一个回合，常用配置为：

```ts
// 2001 的 BuffData 配置片段
{
    id: 2001, name: "休息", class: "rest",
    turnType: BuffTurnEnum.afterTurn, lastTurn: 2,
    notRemove: true,
}
```

通过根技能 `afterSelfBuff: [[2001, 1, 1]]` 添加。当前回合结束经过第一个边界，下一回合结束经过第二个边界后移除，因而跳过下一回合主动行动。

## 12. 被动与战斗中装配

### 装配技能替代普通攻击

单位可装配 `attackSkill`，与 `fbackSkill/supportSkill` 一样保存已学技能 ID：

```ts
a.addSkill(attackId, level);
a.setAttackSkill(attackId);
const equipped = a.getAttackSkill();
a.setAttackSkill(0); // 卸下，恢复原有物理普攻
```

`FightCmdEnum.attack` 和默认的 `none` 指令会优先使用有效的 `attackSkill`；未装配、装配 ID 未学会或已卸下时，使用原有普通攻击。只更换普攻的攻击技能，不把指令改成主动技能。

- 装配的应是攻击类技能，走攻击管线，不分派为治疗、复活等其他 `func`。
- 使用已学等级及攻击者的基础物理/魔法属性，不使用反击属性；倍率、属性生克、暴击、Buff、连击/连招/追击、协战和保护开关照常读取该技能配置。
- 不额外支付配置中的主动费用；发动失败或未命中不再补一次原普攻。
- 检查 `attack` 禁止状态；只禁止 `skill` 的沉默不阻止替代普攻。休息、死亡等行动检查照常执行。
- 保留普攻的敌方选目标、执行时嘲讽和手动守尸规则，不改为该技能的主目标选择规则。目标仍死亡则跳过，复活则攻击原目标。
- 出手消息使用实际装配技能 ID，简报和预解析继续复用现有协议，不需要同步装配状态。

### 被动与技能效果装配

```ts
// PassiveData 配置片段
{ attackSkill: attackId, supportSkill: supportId, fbackSkill: fbackId, addbuff: [[buffId, buffLevel]] }
```

`PassiveSkill.onInit` 只设置普攻/反击/协战的装配 ID，**不调用 `addSkill`、不学习技能、不覆盖实例、不使用被动等级替换主动技能等级**。宿主另外加载单位已学技能。只装配但未学会的技能无法从技能表实例中取出；`attackSkill` 不可用时仍能用原普攻，之后加载对应技能即生效。

`addbuff` 为自己附加 Buff，Buff 等级来自数组中的等级，不自动继承被动等级。初始化时可尚未绑定战斗，构造结束统一重算属性。

技能的命中后公共效果也支持 `attackSkill/supportSkill/fbackSkill`，对施放者改装；同样要求技能另行学会，不刷新当回合协战机会。无伤害装配可配置 `func: "nohurt"`，有伤害技能可同时配置攻击与装配。`attackSkill: 0` 可通过装配效果卸下替代普攻。

当前 `nohurt` 的成功返回值来自加减 Buff 结果；只有装配字段、没有加减 Buff 时仍会装配，但不会因此让入口判定成功，依赖成功返回的 `afterSelfBuff` 不会执行。

## 13. Buff 公共配置

### 计时与监听

| 配置 | 含义 |
| --- | --- |
| `BuffTurnEnum.thisTurn` | 全局回合前；省略 `turnType` 时采用 |
| `BuffTurnEnum.inputTurn` | 单位自己的输入边界，适合一个回合多动 |
| `BuffTurnEnum.afterTurn` | 全局回合后，适合保护、休息 |
| `lastTurn: 0` | 不按回合过期 |
| `lastTurn > 0` | 添加后经过对应次数的边界，在最后一次效果后移除 |
| `times > 0` | 普通次数 Buff 按配置事件消耗次数；特殊类按自身触发规则消耗 |
| `prior` | 带 `ctx` 的监听优先级，小的先执行，相同值按注册顺序 |

同一边界不重复触发，周期遍历使用实例快照；遍历中新加的留到后续边界，被替换或移除的旧实例跳过。普通 Buff 的 `event` 控制次数消耗，不会凭空产生一个未实现的技能效果。

周期 Buff 使用 `func: "heal"` 或 `"poison"`，引用 `skill` 和 `skillLevel`；技能成长按 `skillLevel`，Buff 属性成长按 Buff 自己的等级。周期伤害标记为 Buff 来源，不触发保护分担。

默认监听顺序为：反射 0 → 保护 500 → 不屈 1000。可以按玩法配置优先级；自动复活监听的是死亡事件，收尾执行，不是伤害修改链。

### 清理、驱散与覆盖

- `notRemove`：禁止外部驱散，自然到期、次数用尽仍会移除。
- `dieNotRemove`：死亡时保留；未配置则随死亡清理。
- `notDisplay`：不放入客户端可见 Buff 列表，仍正常结算。
- `tags` 用于分类和筛选，不再通过旧标签控制上述固定行为。
- Buff 驱散强度为自身 `xls.power ?? 0`，移除方技能强度为 `xls.power ?? level`；移除方大于等于 Buff 强度才可驱散。显式 0 有效。
- `RELPACE_BYPOWER` 覆盖先比较 Buff power，同 power 再比较等级；已有实例 power 更高，或同 power 且等级不低于新实例时，保留旧实例。同强度同等级不刷新。
- 自然到期、次数用完、死亡清理不受驱散强度阻拦，清理时解绑监听并重算相关属性。

## 14. 完整行动边界与验证

### 运行异常

战斗运行/行动/输入入口捕获异常后记录错误、立即结束，结果统一为 `FightResultEnum.defend`（攻击方失败）。不继续后续技能、行动或回合，不回滚已经发生的部分效果。Calc 既有检查不变，底层操作仍抛错，由驱动统一收口。默认 `console.error` 保留原始异常堆栈及 `FightErrorContext`，宿主可覆盖 `loop.onError`；客户端只收到普通的 end=1，不传错误堆栈。

异常时清空行动及即时技能队列，关闭输入/大招窗口，释放西游等待与计时器，清理单位 AI/Rule 监听。一名单位清理失败不跳过其他单位；end 回调完成后再广播最终结果，回调异常也判负。`run` 返回防守方胜，烟雨异常即时输入返回 false。回归测试位于 `tests/core/test_fight_error.ts`。

### 怪物 AI 与三个轴的规则

每只 Monster 只有一个 `ai: FightAI`，由 `waitInput` 根据场面决定普通行动。血轴、回合轴、受伤轴改为 `FightRuleHp/FightRuleTurn/FightRuleHurt`，通过 `addRule(rule, prior)`、`removeRule(rule)` 管理，可以多个共存；规则按 prior、注册顺序执行，不争抢输入。切换或清空 ai 不影响 rules。没有 AI 但有规则时普通行动回退普攻；两者均无时保留原固定技能选择。

Boss 切换阶段时可调用 `setAI(AIData 或 FightAI 实例)`、`setRules((RuleData 或 FightRule 实例)[])`；`setAI()` 移除 AI，`clearRules()`/`setRules([])` 清空规则。新配置创建新实例，复用实例保留原计数与阶段；配置中的 prior 生效，直接实例默认 0。替换解绑旧监听并统一重算属性，不影响被动/Buff；新配置无效或绑定失败时回滚本次新绑定，原列表保持。已插入行动条的旧行动按用户规则保留，旧规则的事件收尾回调在解绑后失效。新 AI 从下次 waitInput 生效，不覆盖已提交指令；新周期规则从后续全局回合前边界开始安排额外行动。

怪物模板通过 `ai: AIData`、`rules: RuleData[]` 和 `passiveSkills` 一次装配决策 AI、多条规则及被动。`createAI` 当前支持 `{ type: "rearDoctor" }`；`createRule` 支持 `{ type: hp/turn/hurt, ..., prior? }`，回合规则另有 `pos?: InsertActionPos`。每只怪物都创建独立实例。旧的多轴 ais 数据改为 rules，模板、阵型和宿主 UID 分配方式不变。

`FightAIRearDoctor` 优先普攻敌方存活的后排医生，职业使用 `CarerrEnum.医生`。后排按 `y + 1 > ceil(ny/2)` 判断：3×3 的第 3 排、5×5 的第 4、5 排；内部坐标仍从 0 开始，矩形地图使用高度。多位医生用战斗随机源选一人，无候选或无地图则回退原目标规则；有效嘲讽仍会覆盖攻击目标。通过 `MonsterData.ai: { type: "rearDoctor" }` 即可装配。

- `FightRuleHp(lines)`：每条血线每场一次，比例相加，单次跨多线全部触发；回血、复活不刷新。监听真实 hp 变化，保护分担也触发增攻，不修改基础属性。
- `FightRuleTurn(every, skill, pos?)`：全局第 N、2N…回合，在 processBeforeTurn 插入额外技能行动，默认剩余队列最前；普通行动保留，多条规则均可插入。登记和执行均检查合法性，技能走公共费用/CD 管线，怪物仍按现有资源规则。追加行动不推进 inputTurn。
- `FightRuleHurt(every, skill?)`：保持原即时新攻击逻辑，只统计能攻击时的有效直接受伤；完整 action 后朝伤害来源出手，不走反击链，不进入行动条，不额外收主动费用/CD。移除规则后旧的待执行即时反应失效。

AI 与规则按单位绑定，战斗结束解绑监听，新战斗重置。表现消息 aiHp/aiAttack 保持兼容。规则与 AI 的监听、属性修正可以共用基础能力，但 AI 不能加入规则列表。

### 插入行动

`InsertActionPos.first/last/random/afterSelf` 分别表示剩余队首、队尾、随机间隙、自己的行动后；默认 first。固定位置连续插入保持提交顺序，随机只用战斗随机源。afterSelf 跟随当前或下一条普通行动，自己已行动则回退队首，不打断当前完整 action。速度重排只影响普通行动，afterSelf 项继续跟随其锚点。

调用 `fight.insertAction(unit, input, pos?, ctx?)`，每条独立记录保存自己的指令副本与行动 ID；同一单位可出现多次。插入、取消、跳过会同步客户端行动条。`loop.cancelAction(id)` 取消追加项；同回合最多接受 64 次插入，取消不返还次数。切换回合或结束清理剩余项。

普通 sort 消息仍为 `["sort", uid[]]`；有追加项时附第三项记录数组 `{ id, uid, inserted?, skill? }`。追加出手消息为 `["actor", uid, speed, "insert", actionId]`，客户端每次只移除对应的一条行动，不能用 UID 全部过滤。FightClient.actions 可供图形行动条渲染；简报标注追加技能及追加行动。PC、西游、烟雨共用。即时技能、全体破盾大招及受伤规则的即时攻击保持各自原有行动条规则。

### 全体破盾大招

单位破盾统一发出 `break(unit, ctx, attacker, allBroken)` 上下文事件，`allBroken` 为破盾瞬间本阵营全体存活单位是否破盾的快照。事件在写入 `shield=0` 消息后、本次扣血前触发，只在正数变零时发生；继续受伤、回盾及取消伤害不发。支持 `onContex` 优先级、普通单位监听与全局监听。次数 Buff 配 `event: "break"` 即可按既有生命周期消耗和解绑，派生 Buff 可在 `onEvent` 处理效果。大招通过全局监听登记该事件，不再从单位直接调用大招专用回调；监听 Buff 即使立即回盾，也不取消已发生的全体破盾。

开启 `FightData.allShieldBreak` 后，打破敌方最后一面盾、使所有存活敌人都处于破盾状态时登记事件。必须每个存活敌人都配置盾，无盾者不算破盾；仅移除无盾单位不触发。完整 action（连招、反击、死亡及延迟复活）结束后才发布机会，若战斗已结束则不开放输入。当前动画结束后调用公共 `waitInputUtimate(turn, side)` 选择己方一人，收到合法输入后立刻施放，之后继续普通队列。每队每回合只触发一次，回盾不会取消已触发事件，也不持续轮询破盾状态发放机会。

单位的 `ultimateSkill` 装配已学技能，0 卸下；被动与主动技能配置也支持 `ultimateSkill`。`onInputUltimate(id, { cmd: FightCmdEnum.skill, target, turn })` 使用装配的大招，普通技能输入不能绕过该入口。存活、阵营、禁止技能、休息、目标、cost 与 CD 全部严格检查，无效选择提示后继续等待。大招不推进 `inputTurn`，不占普通行动次数，但照常支付费用并启动 CD；正式尝试消耗整队机会，未发动或未命中也消耗。取消会放弃本回合机会，无有效候选人不弹输入。

PC、西游、烟雨共用这段流程，网络输入必须带当前回合号。`ultimateReady` 消息同步机会，`actor` 的第四项 `ultimate` 表示额外大招行动，客户端不从原行动条移除单位。简报显示机会和大招出手；终局清理客户端待处理机会。

`FightLoopPC` 按速度轮到单位时推进它的 `inputTurn`，玩家/召唤物通过 `input(unit, turn)` 事件等待各自指令，NPC 调用原有 AI。全局 `thisTurn/afterTurn` 与盾恢复仍在全局边界处理。单机保护在本人输入并执行时生效；输入失败提示并继续等待，执行仍复验目标、状态、冷却及资源。输入周期效果与完整行动分别等待对应动画，胜负不会截断反应链，`end()` 释放等待并停止后续回合；接入示例见 README。

PC 即时输入通过 `Fight.checkPC()` 严格检查行动者和目标：普攻拒绝死亡目标，技能的生死、阵营过滤及禁疗/禁毒/禁复活均在输入时校验；`FightSkill.getTargetHint()` 返回对应效果的目标不可用原因，执行函数仍保留自身检查。网游使用 `Fight.checkOnline()` 收指令，保留死亡单位输入和普攻守尸。两个检查入口都返回 boolean，不扣费、不抽样；PC 检查通过后由 `preparePCInput()` 过滤并抽取一次主目标，保存副本。输入拒绝时保持窗口且不扣费、不启动 CD；接受后执行前再复验目标，失效则跳过且不扣费、不启动 CD。此处不修改完整动作后判胜的规则。

状态禁止行为统一读取 `Buffs/FightStatus.ts` 的 `statusForbidActions`，业务入口使用 `isForbid(action)`，不写死眩晕状态名。当前眩晕禁止 `attack/skill/item/escapse/dodge/fback`：禁止 `dodge` 时物理命中检查直接成功，不抽取闪避随机数；普通和技能反击同时检查 `attack` 与 `fback`；每段攻击重新检查 `attack`，行动中途被禁止后不再执行后续连招。协战沿用禁止攻击检查，被动反伤不因这些主动行为禁止而关闭。Buff 眩晕与破盾眩晕共用此规则，解除后恢复原闪避属性。

NPC 配置 `FightAttr.shield` 启用弱点盾，`undefined` 跳过；`attrOri.shield` 保存初始/回满格数，运行中的 `attr.shield` 为当前盾数。弱点攻击或毒伤实际生效时扣 1 格，多项弱点同时命中仍只扣 1 格，未命中、未发动或取消伤害不扣。非弱点伤害不扣盾，反伤、反射和保护分担也不扣盾。

盾未破时受伤减半，此减伤在 `beforeHurt` 之前计算，使保护分担、不屈等读取减半后的伤害；扣掉最后一格的这一击按破盾后的全伤计算。盾为 0 时立即提供 `眩晕` 状态，因此禁止攻击、技能、反击和协战，连招后续段按破盾状态结算。吸血、反伤仍使用实际扣血。盾减伤适用于自身受到的所有伤害来源。

破盾后在下个全局回合的 `processBeforeTurn()` 回满，未破不自动补满，同回合不能重复恢复；恢复只解除盾产生的眩晕，不解除其他 Buff。属性重算、死亡及复活不补盾，新战斗初始化重置。显式初始 `shield: 0` 表示没有可回满的盾，保持破盾状态。客户端通过初始可选 `shield/shieldMax` 和 `["shield", uid, current, "recover"?]` 更新，纳入 `checkSame()`，简报展示相应变化。

主动技能使用 `SkillData.cd` 配置全局回合冷却，默认 0，无冷却；配置必须为非负安全整数。例如第 1 回合施放 `cd: 2`，第 3 回合可再次施放。`unit.getSkillCd(skillId)` 返回剩余回合数。每个单位独立保存各技能恢复回合，重新学习同一技能、死亡及复活不重置，新战斗开始时清空。

提交和执行都检查冷却；队列中相同技能在第一条施放后，后续指令因冷却失效而跳过。通过目标、费用检查，正式尝试施放时开始冷却，概率失败及未命中也消耗 CD；提交失败、费用不足和无可用目标不消耗。此规则共用于各战斗循环的主动施放，装配普攻及连招、追击、反击、协战等反应链不使用主动 CD。客户端通过 `["skillCd", uid, skillId, readyTurn]` 更新恢复回合，随全局回合计算剩余值，无需每回合同步；冷却状态参与 `checkSame()`，简报不额外输出。

`Fight.resolveAction()` 管理进入与退出的嵌套深度。只有最外层正常完成，才执行 `afterAction` 延迟效果并判断胜负；双方全灭是平局，不能截断尚未完成的反应链。

`FightLoopYanYu` 将自动普攻与即时技能分开调度：自动队列按速度执行普攻（含 `attackSkill`），手动只接收当前回合的技能指令，不消耗该单位自动普攻机会。当前完整动作的动画结束后，先处理按提交顺序排队的技能，再继续普攻；不打断反应链，技能出队时重新校验目标、状态及费用。即时技能用 `actor` 第四项 `"skill"` 标识，客户端不因此移除待普攻条目。宿主通过 `waitDrawOver()` 等待每次动作的实际动画，回合末不重复等待。接入示例及范围见 README 的“烟雨式自动普攻与即时技能”，测试位于 `tests/core/test_yanyu.ts`。

宿主组合底层操作时使用 `fight.resolveAction(() => { ... })` 包住完整行动。作用域外的 `afterAction` 立即执行。异常退出会丢弃待处理任务，不把部分结算当成功结果；攻击次数、嵌套深度和行动后效果设有 64 的限制，超限抛出 `Reaction limit`。

全部随机通过 `Fight` 随机源。客户端根据增量消息更新，技能及 Buff 名称从本地表查，不通过 `sync` 修正状态。简报区分 `【连击】`、`【连招】`、`【追击】`、`【反击】`、`【协战】`。

简报只给每行开头的人名加阵营色：攻击方绿色，防守方红色，跳过行首连击、协战等标注；后续出现的人名不着色，行动条列表保持原色。技能、Buff、伤害、治疗及未命中沿用各自配色，死亡和复活整句颜色优先。保存的 `lines/toString()` 及关闭颜色后的输出均为纯文本。

### 文字与图形共用的表现预解析

`FightPreParse` 位于 `src/fight/Client/FightPreParse.ts`，从包入口公开导出。`FightReport` 已使用它，不再自行识别协战与保护配对。图形客户端使用同一类组织播放关系：

```ts
const parser = new FightPreParse();
const plan = parser.parse(msgs);
```

| 结果 | 用途 |
| --- | --- |
| `plan.messages` | 完整原消息，顺序与内容保持不变，状态更新仍逐条执行 |
| `kind: "support"` | `attack` 与 `support` 是同时出手的两个成员 |
| `kind: "protect"` | `share` 与 `target` 是同时受伤的两个成员 |
| 成员的 `index/message` | 本批消息下标与原消息引用，供消费者关联、定位和排程 |

协战分组在主攻位置安排双方出手；协战的伤害和未命中结果仍留在原结算位置。保护分组在两条伤害状态均处理完后呈现双方受伤，死亡及后续消息不并入受伤组。两种分组可以交叠，例如主攻与协战各自造成一次保护分担。原消息只应用一次，组成员引用不能再重复更新客户端。

预解析不生成文字、不处理颜色、不计算伤害，也不改写、删除或重排原协议。它只跨批保存阵营 ID 信息，读取本地技能 `nosupport` 禁止字段；普通攻击 ID 0 也可关联协战。宿主使用其他配置表时，可给构造函数传入“是否允许协战”的查询函数。一个展示流使用一个解析器，`start` 重置阵营信息。只在当前批内分组，拆批或关联不明时保留独立消息，不把旧批次残留带入新动作。此阶段是表现计划，不是战斗执行或恢复接口。
