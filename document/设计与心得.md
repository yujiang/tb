# 心得
1. 扩展
skill的特殊性，是通过func来解决的，所以没有从FixSkill在衍生特殊的skill；
skill只有process一下，func基本够用了；
而buff不同，贯穿了各个战斗周期，所以需要派生不同的buff。
2. 字段
字段不能过于精简，也要考虑表达。
程序的逻辑不再用hasTag, tags一般用在数据的逻辑。
字段需要细细推敲，比如next跟combo，只有一个继承主目标的不同，但是分开理解起来容易。
3. Msg
尽量精简，客户端查表可以得到的数据不必传输

# 技能设计
1. protect保护
protect速度放在最前
先看buffprotect, 在视觉上我们应该看到 被保护者和保护者同时受伤，同为了效果，保护者没有后续受伤逻辑了（比如反击反弹），不然就很乱；

2. 协战support
就是A,B是同一方的，A装备了supportSkill(类似反击backSkill，是装上去的，有可能是passiveskill加的，有可能是战斗中装的)
B用skill攻击C，如果skill可以助战: 类似 fback?: boolean加一个support
那么B打了C后，紧跟着A也用skill打C(rand有几率不打)，然后再next->fback...
并且每一个回合A只能support一次
如果本方有多个support，那么先选一个（随机）来support，当然support本身有rand，可能无事发生。

3. combo
继承主目标
有combo，不受到反击和反伤（否则表现不好看）
反击和反伤发生在最后一次，需要把前面的伤害累积起来。(可能通过ctx来传递这个)

4. relife自动复活
自动复活有问题，我看了别的游戏是这次行动结束之后再复活，否则3连2连打死复活被第三连打死了就没有意义了。
已改为：整次行动及其反应链结束后，再自动复活，随后判断胜负。
