# 怪物与行为

[返回目录](./index.md) · [架构职责](./架构与流程.md)

源码：[MonsterData](../../src/fight/Unit/MonsterDatas.ts)、[MonsterSide](../../src/fight/MonsterSide.ts)、[AIData](../../src/fight/AI/AIDatas.ts)、[RuleData](../../src/fight/Rules/RuleDatas.ts)、[ZhenData](../../src/fight/ZhenDatas.ts)。

AI 和 Rule 的具体实例分别由 [AIFactory](../../src/fight/AI/AIFactory.ts) 与 [RuleFactory](../../src/fight/Rules/RuleFactory.ts) 创建。基类模块 `FightAI`/`FightRule` 重导出创建函数，与 Buff 一致；原数据模块的函数导入路径及包入口保持兼容。`AIData`/`RuleData` 只作为类型使用时应写 `import type`，不引入具体实现的运行时依赖。

## MonsterData 全部字段

| 字段 | 含义 | 缺省与规则 |
| --- | --- | --- |
| `id` | 怪物模板 ID | 0 有效，可重复实例化；不是战斗 uid |
| `name` | 继承 FightDisplay 的名称 | 必填，初始化传给客户端 |
| `character` | 继承的人物描述表数字编号 | 可省略，0 有效；原样写入display并随入场消息发送 |
| `weaponName` | 实际使用的兵器显示名称 | 可省略；原样写入display，MUD的$w读取此值，不影响兵器类型或结算 |
| `wugong/neigong/qinggong` | 分别引用passive表的格挡/减伤/闪避文案 | 输入可省略，display统一补0；仅表现，不自动学习被动或改变属性 |
| `attr` | 完整 FightAttr | 实例或同结构 JSON，生成时深拷贝并恢复属性类 |
| `skills` | 已学主动技能 | `[技能ID, 等级][]`，缺省空，等级 0 有效 |
| `passiveSkills` | 初始被动技能 | `[被动ID, 等级][]`，缺省空；在主动技能学习后初始化 |
| `attackSkill` | 初始替代普攻装配 | 缺省保留被动装配，0 卸下；只装配不学习 |
| `fbackSkill` | 初始反击装配 | 缺省保留被动装配，0 卸下 |
| `supportSkill` | 初始协战装配 | 缺省保留被动装配，0卸下；必须是已注册的normal技能（func省略同normal），否则装配时断言失败；只装配不学习，未学时不参与协战 |
| `ultimateSkill` | 初始破盾大招装配 | 缺省保留被动装配，0 卸下；由自身破盾后自动触发 |
| `inputSkill` | 无 AI/规则时的固定主动技能 | 缺省/0 取技能首项，再没有则普攻；烟雨原自动路径不读取旧 inputSkill |
| `ai` | 唯一决策配置 | 可省略；createAI 为每只怪物创建独立实例 |
| `rules` | 固定行为配置列表 | 可省略；多条共存，每只怪物独立计数 |
| `extraAction` | 每回合额外行动 | `[速度倍率, 技能ID][]`，可省略/空；进入行动条，0技能重新走AI，无AI普攻；与动态插队每回合合计最多64条 |

装配顺序：属性/显示 → 学习技能 → 初始化被动和附加 Buff → 模板显式装配和额外行动 → 规则和 AI。显式 0 会覆盖被动装配，省略则保留。初始生命为 0 时创建死亡单位并走死亡清理。

```ts
initMonsters([{
    id: 1001,
    name: "山贼首领",
    attr: bossAttr, // 宿主提供完整FightAttr
    skills: [[101, 1], [102, 1]],
    passiveSkills: [[201, 1]],
    attackSkill: 101,
    ai: { type: "target", career: "医生", pos: "back" },
    rules: [
        { type: "hp", lines: [{ hp: 0.7, buff: [2101, 1] }] },
        { type: "turn", everyTurn: 3, skill: 102 },
        { type: "hurt", everyHurt: 2 },
    ],
}]);
```

示例 ID 的技能、被动、Buff 需先注册，装配不会自动补学。

## AIData 全部字段

AIData使用平铺配置，工厂只内置target；旧cond类型合并到target，通过self、cond和condData组合表达条件施法。旧rearDoctor/topThreat/topHealer/lowHpHeal类型也不再注册。

| 字段 | 含义 | 缺省、范围与入口 |
| --- | --- | --- |
| `type` | 必填类型字符串 | 仅target；条件、选人和技能组合配置，未知类型报错 |
| `skill` | 已学技能ID | 正安全整数；省略使用装配普攻或默认普攻，不自动学习，不使用独立大招槽 |
| `self` | 是否选择自身 | 缺省/false不启用；true在条件通过后优先于贡献和职业/站位筛选，仍须符合技能目标资格 |
| `friend` | 职业/站位筛选阵营 | 缺省false敌方，true己方；不改变贡献榜来源 |
| `contributions` | 贡献来源 | 缺省不使用；unitHurt自身受伤榜、unitHeal自身受疗榜；enemyHurt/enemyHeal敌方阵营输出/治疗榜；friendHurt/friendHeal己方阵营输出/治疗榜。有限正值降序，同分保持记录顺序 |
| `career` | 职业字符串 | 缺省/空串不限，与attr.career精确比较，如医生 |
| `pos` | 站位规则字符串 | 缺省/空串不限；back按行号大于ceil(ny/2)选后排，需要地图，未知非空值无候选；与RuleData.pos无关 |
| `cond` | 选人前置条件 | 省略/空串不限制；hpLow表示存活且HP比例严格小于condData；未知非空值不通过 |
| `condData` | 条件参数 | hpLow读取生命比例阈值，通常[0,1]，0.5表示50%，显式0有效，省略时hpLow不成立；无条件时不读取，getXls().condData可读 |

判断顺序为条件 → self → 有效contributions → 职业/站位筛选；有效contributions优先于职业/站位筛选，逐个过滤离场、死亡及技能不接受的候选。职业和站位可组合，仅筛职业无需地图。多人使用战斗随机源选一个，单人不抽样。无候选时返回undefined，由怪物回退普攻。全局duiwei仅控制自动普攻，显式目标和嘲讽仍可覆盖默认对位；技能自身配置的duiwei仍然有效。

旧配置对应的新写法：

```ts
{ type: 'target', career: '医生', pos: 'back' } // 后排医生
{ type: 'target', contributions: 'unitHurt', skill: lethalId } // 自身最高仇恨
{ type: 'target', contributions: 'enemyHeal', skill: lethalId } // 敌方最高治疗贡献
{ type: 'target', self: true, cond: 'hpLow', condData: 0.5, skill: healId } // 低血自疗
```

AI 不额外插入行动，它决定自己的普通行动。每只怪物只有一个 AI；`waitInput` 返回 undefined 时回退普攻。无 AI 且无规则时保留旧固定技能选择；只有规则时普通行动为普攻。

## RuleData 全部字段

RuleData使用单一平铺结构，方便XLS表采用一组固定列：`{ type: string; prior?: number; lines?: HpAxisLine[]; everyTurn?: number; everyHurt?: number; skill?: number; pos?: InsertActionPos; speedRate?: number; shieldAdd?: number }`。常用字段直接展开，不按类型拆联合结构，也不放入typeParam。可选标记表示该列并非每类规则都要填，实际必填项由工厂和具体规则校验；与当前类型无关的列不读取。

| 字段 | 含义 | 缺省、适用类型与边界 |
| --- | --- | --- |
| `type` | 规则类型 | 必填字符串；hp血轴、turn回合轴、hurt受伤轴、shieldAdd破盾成长，未知值工厂报错 |
| `prior` | 规则执行顺序 | 各类通用，有限数，缺省0；小的先，同级按添加顺序，不是事件监听器优先级 |
| `lines` | 血线列表 | hp必填，允许空数组；按hp严格递减填写，直接进入当前血量对应的最深阶段，不修改原数组和Buff元组；其他类型忽略；元素见下表 |
| `everyTurn` | 全局回合间隔 | turn必填，正安全整数，无缺省值；hurt/hp忽略 |
| `everyHurt` | 有效直接受伤次数阈值 | hurt必填，正安全整数，无缺省值；turn/hp忽略 |
| `skill` | 使用的已学技能ID | turn必填且按普通技能校验，不使用独立大招槽；hurt可省略，缺省普攻/装配普攻；指定技能统一按普通技能收费和启动冷却，费用/CD留空则不消耗；提供时为正安全整数；hp忽略 |
| `pos` | 固定行动插入位置 | 仅turn使用；显式配置优先于speedRate，省略按速度倍率排序；hp/hurt忽略，枚举见后文 |
| `speedRate` | 行动速度倍率 | 仅turn且pos省略时使用；非负有限数，缺省1，0有效；按当前getSpeedOrder()×倍率插入并随速度重排，不修改单位速度，不推进输入次数或集气；hp/hurt忽略 |
| `shieldAdd` | 每次破盾后为下次回满增加的层数 | 仅shieldAdd规则使用，必填正安全整数；破盾时按初始盾层数 + shieldAdd × 破盾次数更新并同步上限，当前盾保持0，下回合按新上限回满 |

### HpAxisLine 的两个字段

| 字段 | 含义 | 校验与计算 |
| --- | --- | --- |
| `hp` | 当前生命比例血线 | 有限数 `(0,1]`；hp/hpMax 小于等于它就触发，初始生命已低也算 |
| `buff` | 阶段Buff的[ID,等级] | 必填二元组；Buff需先注册，ID为正安全整数，等级为非负安全整数，0级有效；切换时先强制移除旧阶段Buff再添加本项 |

血线每条每场一次，回血不回退；新战斗重置。血线配置必须按a>b>c严格递减，构造时拒绝乱序或重复，不做运行时排序。一击跨越多条血线时直接进入最深阶段，只添加最终阶段Buff，跳过中间阶段及其回调和消息。严格先移除旧Buff，再添加新Buff；移除不受notRemove/power限制，同ID也能换成新等级。效果完全由Buff定义，复用属性、状态、周期、次数、持续时间和客户端增删流程，不修改attrOri；血轴本身不再提供attackRate。Buff自行到期或被驱散后，不会因重复跨过旧血线而补加。死亡清理依照Buff.dieNotRemove，需要复活后保留阶段效果时设true。

回合轴保留普通行动，额外插入独立行动并显示在行动条。受伤轴保持即时新攻击：完整 action 后朝刚才攻击者出手，不进条、不推进输入次数；指定skill时统一走普通技能的费用和冷却，填表留空则不消耗；Buff、反伤、反射、分担和零伤害不累计。二者不能因为都“额外攻击”就合并成同一种调度。

## 插入位置

| InsertActionPos | 值 | 含义 |
| --- | --- | --- |
| `first` | 0 | 剩余队首，默认；连续插入按提交顺序 |
| `last` | 1 | 剩余队尾 |
| `random` | 2 | 剩余队列的随机间隙，只用 Fight.random |
| `afterSelf` | 3 | 当前/下一条自己的普通行动后；自己已行动则回退队首 |

不打断当前完整 action。速度变化重排普通行动时，afterSelf 项继续跟随其锚点。一次全局回合最多接受 64 次插入，取消不返还预算。宿主也可直接 `fight.insertAction(unit, input, pos, speedRate, ctx)`；带 ctx 可与本次结算消息一起发送。该入口仅在pos省略且提供speedRate时按倍率参与速度排序；pos和speedRate都省略仍按队首固定插入。FightRuleTurn则默认传入倍率1，填写pos时优先使用位置。行动条协议见 [客户端](./客户端与表现.md)。

## Boss 阶段切换

```ts
boss.setAI({ type: "target", career: "医生", pos: "back" });
boss.setRules([
    { type: "turn", everyTurn: 1, skill: rageSkillId },
    { type: "hurt", everyHurt: 2 },
]);
// boss.setAI();       // 移除AI，不影响rules
// boss.clearRules();  // 清空rules，不影响AI、被动和Buff
```

`setRules` 接受 RuleData 或 FightRule 实例；新配置创建新状态，复用实例保留原计数/阶段，实例形式的 prior 默认 0。非法配置、重复实例、跨单位复用或初始化失败时保留原列表并清理本次绑定。

**已进入行动条的旧规则行动保留。** 新 AI 从下一次 waitInput 生效，不覆盖已提交指令；新周期规则从之后的回合前边界安排。移除规则后，旧受伤规则尚未执行的事件收尾回调失效。

## ZhenData 全部字段

| 字段 | 含义 | 规则 |
| --- | --- | --- |
| `id` | 阵型表 ID | 0 有效；原生MonsterSide消费位置，XLS组队同时读取mapsize |
| `pos` | 平面位置数组 | 从 0 开始；按 ids 列表顺序分配，已用位置需非负安全整数且互不重复 |
| `mapsize?` | 地图尺寸[宽,高] | 两个正安全整数，如[5,5]；createSideByXls必填，Fight.createSide按双方配置自动建图并校验一致；旧MonsterSide入口可省略 |

`CreateMonsterSide(ids, zhen, allocateUid)` 接受模板 ID 列表（允许重复）、阵型 ID 和宿主 UID 分配函数。`getZhenPos` 返回副本；位置可多配，取前 N 项，少于怪物数报错。地图上界由宿主按 nx/ny 保证。双方共享 UID 分配器，避免跨阵营碰撞。

## 选目标AI与个人贡献

`new FightAITarget({ type: "target", contributions: "unitHurt", skill: 致死技能ID })` 对自身 `enemyHurt` 中最高有效贡献者施法；`{ type: "target", contributions: "enemyHeal", skill: 致死技能ID }` 读取对方 `FightSide.heal`，对最高有效治疗者施法。任何选择方法省略 skill 都使用普攻，也可以将职业和后排筛选与致死技能搭配。缺少候选、未学习、冷却、封印、休息等导致技能不可用时返回 undefined，沿用普攻回退；嘲讽仍在执行阶段重定向。

最高贡献选择先排除死亡、石化、离场、转阵营或不符合技能资格者，同分按首次贡献记录顺序，不抽样。后排医生多人时使用战斗随机源。AI只决定普通行动；低血量自疗、低血量优先打指定职业等策略，统一使用cond/condData组合self、贡献或职业/站位筛选。只有现有配置无法表达的策略才扩展findTarget。

`FightSide.hurt/heal` 是以来源 UID 为键的累计 Map，分别记录本阵营成员造成的实际生命扣除和恢复，按输出来源归属，不按受作用者归属。过量伤害和溢出治疗不多计，回血含自疗、吸血、周期及复活等 onHeal 来源；单位自身 friendHeal 同步按实际恢复量记录。来源或受作用者死亡、离场都不会清除阵营历史。

`side.getContributions()` 返回独立的 `{ uid, hurt, heal }[]`，包含当前零贡献成员和有贡献的离场成员，适合宿主战后展示；结果可自行排序，不会改变战斗中的单位或 Map。`clearContributions()` 可显式清空，`Fight.createSide` 绑定阵营时也会清空。结束战斗保留记录，未新增客户端网络消息，由宿主选择发送和持久化。

## extraAction 与 SpeedSkill

`extraAction: [[0.5, 0]]` 让 Boss 每回合在原行动外再有一个半速行动位；`[[1, 0]]` 使用同速行动位，`[[0.5, 101]]` 在半速位置执行已学技能101。可列多项，每项生成独立行动ID，下一回合重新生成，不逐轮累计。

| 元组位置 | 含义 | 范围和入口规则 |
| --- | --- | --- |
| 0 | 当前速度倍率 | 必填，非负有限数；0为零速度，1同速，0.5半速，>1可先于普通行动；按当前getSpeedOrder（含本场乱敏）乘倍率排序 |
| 1 | 技能ID | 必填，非负安全整数；0在出手时重新调用AI，无AI则普攻；正数须已学习且不能是ultimateSkill槽 |

PC、West、YanYu共用行动记录；West/YanYu中配置了extraAction的怪物会把普通行动的AI决策也延后到实际出手，避免较快的额外行动执行后还使用旧场面指令。每条额外行动执行前复验死亡、休息、封印、目标、CD和资源；无效固定技能直接跳过。额外行动不调用inputStart，不重复推进inputTurn和输入周期Buff。

减速或加速时只重排剩余普通行动和模板额外行动，已完成的不会重新加入；动态插队保留原有位置语义。同速按稳定队列顺序。配置在MonsterSide创建时逐项复制，可通过`monster.setExtraActions(list)`替换下回合配置；原模板和其他实例不共享元组。

死亡只会跳过当前轮到的那条行动，不会批量删除本回合剩余行动记录。Boss首段轮到时仍死亡则跳过，若同伴在第二段前复活它，第二段沿用原行动ID并正常出手（技能0重新走AI）；两段都已在死亡时跳过后才复活，则不会补回旧行动。PC、West、YanYu均按此边界执行，客户端同步保留/移除对应的独立行动。

## 低血自疗AI

`{ type: "target", self: true, cond: "hpLow", condData: 0.5, skill: 治疗技能ID }` 由工厂创建独立 `FightAITarget`。当 `hp < hpMax × 0.5` 时，尝试对自身施放配置技能（此例为heal）；恰好50%或以上、已死亡、未学习、技能目标不符、冷却、封印、休息、禁疗、石化等不可施放情况返回undefined，不修改指令，沿用怪物默认普攻回退。治疗无需手工扣费或加血，仍经公共技能流程。

同回合每次AI决策都按当前血量判断；额外行动第一次自疗达到50%后，第二次恢复默认普攻。条件与选人已合并到FightAITarget；省略cond直接选人，未知条件不通过。未配置self、有效贡献或职业/站位时，没有选人结果并回退普攻。

## AI和Rule的xls构造入口

与Buff一样，AI/Rule构造函数接收完整配置对象，由公共基类FightBehavior保存为protected xls；`getXls()`返回原配置；AI条件参数读`getXls().condData`，各规则使用对应的显式字段。工厂原样传入配置，保留 `prior` 和各规则字段。内置实现不修改xls，状态和监听仍由各实例持有；Hp规则仍复制血线数据用于实例计算。

直接构造使用`new FightRuleHp({ type: "hp", lines: [...] })`、`new FightRuleTurn({ type: "turn", everyTurn: 3, skill: id })`、`new FightRuleHurt({ type: "hurt", everyHurt: 3 })`、`new FightAITarget({ type: "target", self: true, cond: "hpLow", condData: 0.5, skill: id })`。原位置参数入口已统一改为xls对象；FightAI为抽象基类，代码扩展需要向super传完整配置并实现findTarget(unit, turn, skill)，返回目标或undefined；基类waitInput统一取技能、生成指令并预检。自定义waitInput仍可覆盖。Rule仍可无参创建，默认`{ type: "custom" }`不代表工厂注册了custom类型。

### 血轴Buff的初始化与运行时规则管理

模板或代码在初始化时配置血轴，可不提供ctx：怪物完成规则绑定后按当前HP初始化阶段，尚未绑定Fight也可添加Buff；FightLoop.start重新计算阶段，最终Buff由初始单位消息同步。直接对普通单位调用rule.bind仅建立监听，需调用rule.startFight(unit)初始化当前血线。

运行时使用`addRule(rule, prior, ctx)`、`removeRule(rule, ctx)`、`setRules(list, ctx)`、`clearRules(ctx)`，传入当前动作上下文并广播其msgs；事件回调内复用该事件的ctx，不另建和提前广播中间状态。整组换规则停止旧规则监听再初始化新规则，旧规则已经添加的Buff保留，新旧Buff的叠加或覆盖依照Buff.overlap；保留同一规则实例则不重置阶段。显式移除规则只解绑规则监听，不清理已经产生的Buff。只有仍在运行的同一血轴规则推进阶段时，才先移除该规则实际持有的旧Buff再添加新Buff；如果旧实例已被其他逻辑移除或替换，不误删新的同ID实例。战斗结束仅解绑监听，最终Buff展示仍保留；离场使用单位既有清理流程。

表现消息为`['aiHp', uid, hp血线, BuffID, 等级]`，同时发送常规removeBuff/addBuff消息。示例Buff 2101/2102需要先通过initBuffs注册。
