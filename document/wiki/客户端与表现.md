# 客户端与表现

终端试玩入口为 [fmud.ts](../../src/tools/fmud.ts)，运行 `fmud.bat fightId side1Id side2Id [seed]`，详见 [操作说明](../../README.MD#fmud终端试玩)。复用FightMud，按全局配置 `loopType` 通过 `createFightLoop` 创建PC、烟雨或西游循环。仅FightMud战斗描写通过 [ConsoleLineRenderer](../../src/tools/ConsoleLineRenderer.ts) 默认每200ms显示一行，队列排空即绘制完成，无需确认。战况整块输出，保持与战斗描写的前后顺序；启动信息、技能列表、帮助和提示直接显示，不逐行延时。玩家输入提示等前面的战斗描写显示完再出现。退出取消定时器和积压文字。最多一边user，双monster全自动。通过.env选择fight_global、常量与JSON目录，FMUD_LINE_MS只设置战斗描写行间隔（非负整数毫秒，默认200，0关闭延迟），不改变底层战斗规则。

战况在每回合初收到首次行动条时自动显示一次，等待输入时可用show查看即时战况，不消耗行动；status和状态保留为别名。换人、输入重试和回合内行动条重排不会重复自动显示。

`q` 重复当前单位上次成功提交的指令，每个单位独立记录，保留技能与显式目标，仍校验当前状态、费用和冷却；无记录时继续等待输入。烟雨用 `单位UID q` 重复该单位上次即时技能，自动普攻不覆盖记录。退出用 `quit` 或 `退出`。

防御实际执行后发送 `['defend', 单位UID]`，UID为0有效；简报和MUD据此显示防御动作。消息进入当前动作的ctx.msgs，跟随普通广播与绘制队列，不从输入提交时提前显示。

## 显示与逻辑分离

客户端接收增量消息维护状态，不重算伤害，也不靠每一步 sync 掩盖服务端/客户端差异。`checkSame` 用来验证已经收到的状态与服务端一致；它不是完整快照恢复或录像。

服务端不在每条攻击消息里重复传人物、技能或 Buff 名。人物名来自初始化，技能/Buff 名来自客户端本地表。图形渲染与文字简报都应消费协议，而不是拿简报字符串当逻辑数据。

### FightDisplay 全部字段

| 字段 | 含义 | 缺省 |
| --- | --- | --- |
| `name` | 单位显示名 | 宿主必填 |
| `character` | xlsCharacter 描述表键，数字或字符串 | 可省略，0 有效；不参与战斗数值 |

## 状态与主要消息

`FightClient` 保存 fid/turn/result/winSide/runaway、两方 sides、剩余 uid 顺序 sort、当前 actor、行动描述 actions。初始单位还包含 uid、pos、dead、display、point、可见 Buff，以及可选盾/技能冷却。结果类型与胜方分开，`result` 是 FightResultEnum，`winSide` 只取 -1/0/1。

HP/MP/SP/JP 的正式战斗变化都必须通知客户端：HP 受伤和治疗通过 `onHurt/onHeal` 产生 `hurt/heal`，四种费用通过 `costSkill` 产生对应 `costHp/costMp/costSp/costJp`，MP/SP/JP 恢复或增长通过 `addMp/addSp/addJp` 产生 `addPoint`。消息进入当前 `ctx.msgs`，由循环统一广播；宿主直接调用这些入口时，也需把该上下文消息发送给客户端。全局 `jiqi` 未开启时不计算集气、忽略 JP 费用，`side` 的 point 省略 `jp/jpMax`，也不发送集气增减消息；开启时才同步完整四槽。正式运行时通过上述入口修改资源。

| 消息 | 主要内容 | 用途 |
| --- | --- | --- |
| start/side | 战斗 ID、阵营和初始单位 | 建立客户端状态 |
| turn | 全局回合 | 开新回合 |
| sort | uid 列表，可附行动描述数组 | 更新剩余行动条 |
| actor | uid、速度、可选行动种类/ID | 开始表现一条行动 |
| skill/miss | skillId、攻击者、目标、可选反应标记 | 出手或未命中 |
| hurt | why、目标、来源、实际扣血、剩余生命、effects | 直接使用剩余生命更新 |
| heal | why、目标、来源、恢复数值、治疗前生命、effects | 截断到最大生命更新，注意与 hurt 的生命字段不同 |
| costHp/costMp/costSp/costJp | uid、消耗、剩余值 | 更新对应资源费用，支持 HP/MP/SP/JP |
| addPoint | uid、资源键 mp/sp/jp、实际增加值、最终值 | 资源恢复及怒气、集气增长；客户端直接采用最终值 |
| skillCd | uid、skillId、恢复回合 | 按全局回合显示冷却 |
| weakness | uid、'prop' 或 'weapon'、对应枚举值 | 首次有效命中时揭示一项弱点，已揭示项保存在单位的 revealedWeakProp / revealedWeakWeapon |
| weaknessAll | uid、五行弱点数组、兵器弱点数组 | 成功观察时一次同步完整列表，覆盖目标的 revealedWeakProp / revealedWeakWeapon；无弱点用空数组 |
| shield | uid、当前盾、可选 recover（也可为 null）、可选新上限 | 扣盾、破盾与回盾，破盾成长时第五项同步新上限 |
| addBuff/removeBuff | 单位、来源、Buff ID、等级/展示时长等 | 维护可见实例；隐藏 Buff 不进入列表 |
| skipAction | uid、Buff ID，或 null 加状态名 | 显示跳过行动原因；被动状态没有 Buff 来源时使用状态名 |
| aiHp | uid、血线比例、BuffID、等级 | 显示进入血轴Buff阶段；真实状态由removeBuff/addBuff同步，切换先移除再添加 |
| buffTimes | unitId、buffId、remaining | 更新剩余次数；归零后跟随 removeBuff，隐藏 Buff 不发送 |
| die/relife | uid | 更新死亡标记 |
| dismiss | 操作者uid、离场单位uid | 删除离场单位及其全部行动记录，不表现为死亡；服务端随后同步sort |
| summon | 主人uid、阵营、新宠完整展示数据 | 追加新宠，本回合不增加行动条；替换时先处理旧宠dismiss |
| runaway | 行动者 uid、成功布尔值 | 表现逃跑成功/失败；成功标记整场逃跑，仍由 end 提供最终结果 |
| end | result、winSide、runaway | 清空行动条并通知宿主收尾；result 不用作阵营数组下标 |

结束消息为 `["end", result, winSide, runaway]`，客户端的 `result` 替代旧 `win` 字段。`start` 会清空逃跑标记并把结果和胜方恢复为 -1。仍支持读取旧两项 end 消息：平局/超时按当前规则将胜方解析为防守方。简报/MUD 输出逃跑成功、失败及超时结果。

可见 Buff 元组为 `[id, level, start, lastTurn, times]`，初始化使用当前剩余次数；`addBuff` 第七项为 `[start, lastTurn, times]`，隐藏时为 null。`buffTimes` 为 `["buffTimes", unitId, buffId, remaining]`，只更新已存在的展示项，不创建新实例。

协议精确下标与扩展消息以生产端和 FightClient/FightReport 为准；此表解释用途，不冒充完整版本化网络协议。

## 追加行动与 FightActionDisplay

普通 sort 为 `["sort", uid[]]`；有追加项时第三项为完整行动描述数组。同一 uid 可以出现多次。

| 字段 | 含义 | 缺省 |
| --- | --- | --- |
| `id` | 本场独立行动 ID | 必填，用来区分重复单位 |
| `uid` | 行动者 uid | 必填，可以重复 |
| `skill` | 追加技能的技能 ID | 普通行动或追加普攻可省略 |
| `inserted` | 是否独立追加行动 | 省略表示普通行动 |
| `speedRate` | 模板额外行动速度倍率 | 可省略；0有效，出现时表示该行动随单位速度参与排序，动态插队不设置 |

模板额外行动带`inserted: true`和`speedRate`，正数技能还带skill；0技能在实际出手时由AI决策，因此预览不固定技能。追加出手是 `["actor", uid, speed, "insert", actionId]`，模板行动的speed显示为当前单位速度乘倍率，客户端只移除该记录；普通出手也只删第一个匹配项。即时技能标记 skill、破盾大招标记 ultimate，不从普通行动条移除单位。

## proParse：表现分组

实际类名为 `FightPreParse`，它将同批协议中可关联的保护双伤、主攻与协战放到分组结构，供 FightReport 或图形渲染复用。保留原消息引用与下标，不重新结算、不更新生命、不生成新协议，也不重复把消息应用到客户端。

只合并当前批次中已经确认的关系；拆批、关联不明时各自显示，不预测概率。保护双方伤害可以合成一句；协战可合成同时出手，服务器结算仍有先后。

## MUD 三张表与全部字段

### FightMudTables

| 字段 | 含义 | 缺省与匹配 |
| --- | --- | --- |
| `xlsCharacter` | character → 人物特征表 | 可省略；键 0 有效 |
| `xlsText` | 人物专属或特征组合文案 | 可省略；人物键是专属，其余键用 + 连接特征值 |
| `xlsSkillDesc` | 技能 ID → 文案 | 可省略；同一事件字段有内容时优先级最高 |

逐事件字段回退：技能专属 → 人物专属 → 匹配特征组合 → 内置描写。空白文案视为未配置；组合命中特征越多越优先，同具体程度按表顺序。三张表只在客户端使用，不参与战斗结算或传输。

### MudCharacter

所有字段都是可选字符串，取值由宿主约定。它们不是服务端属性枚举，不会自动映射职业、性别或武器规则。

| 字段 | 含义 | 示例 |
| --- | --- | --- |
| `武功` | 武功层级特征 | 绝顶、高手、普通、菜鸟 |
| `sex` | 性别文字特征 | 男、女；占位符也支持性别 |
| `年纪` | 年纪特征 | 少年、青年、中年、老年 |
| `相貌` | 相貌特征 | 英俊、普通、丑陋 |
| `兵器` | 兵器文字 | 刀、剑、棍；可以与 WeaponEnum 列表不同 |
| `门派` | 门派文字 | 华山、武当、少林 |

### MudTexts

| 字段 | 描写事件 | 缺省/颜色 |
| --- | --- | --- |
| `出手文本` | 技能出手 | 可省略，逐级回退 |
| `受伤文本` | 技能直接受伤 | 可省略；{伤害} 输出红色或暴击橙色数值 |
| `死亡文本` | 死亡 | 可省略，整句暗红 |
| `未命中文本` | 物理未命中 | 可省略；{未命中} 输出蓝色文字 |
| `治疗文本` | 恢复生命 | 可省略；{治疗} 输出绿色数值 |
| `复活文本` | 复活 | 可省略，整句亮绿 |

常用占位符：`{人物}`、`{施放者}`、`{目标}`、`{技能}`、`{伤害}`、`{治疗}`、`{生命}`、`{最大生命}`、`{未命中}`。人物特征可用 `{武功}`、`{性别}`，以及 `{施放者门派}`、`{目标兵器}` 等前缀。未知占位符保留原文。

反伤、反射、分担、周期伤害不会误借攻击技能的受伤文案；治疗与复活协议没有技能编号时也不猜。MUD 是表现副产品，不应反过来增加战斗内核的复杂度。

## 简报颜色约定

技能名和 Buff 名使用各自颜色并加方括号；加血数字绿、普通伤害数字红、暴击数字橙；“未命中”三个字蓝，死亡整句暗红、复活整句亮绿。回合与行动前留空行。人物着色以当前 FightReport 输出策略为准，不应从文字反推阵营或战斗状态。

验证：[客户端](../../tests/core/test_client.ts)、[简报及MUD](../../tests/report/)。

回合规则的速度倍率行动同样在 `FightActionDisplay.speedRate` 中同步，0有效；出手 `actor` 中速度为单位当前速度乘该倍率，按行动ID只移除本条记录。显式pos的规则行动不携带倍率。
