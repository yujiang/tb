## FightGlobalData：启动时设置的公共规则

宿主启动时调用一次 `setFightGlobalData({...})`，之后创建战斗只传表格行。`getFightGlobalData()` 查询完整公共配置，`fight.globalData` 读取同一份进程共享规则。设置入口接受 `Partial<FightGlobalData>`，省略字段保留当前值；配置合法性由宿主保证，库不做运行时校验。所有战斗统一读取公共配置，若再次设置，也会影响已有战斗。测试按场景初始化并恢复配置；正式宿主按启动时一次设置使用。

| 字段 | 含义 | 缺省与边界 |
| --- | --- | --- |
| `maxTurn` | 全局回合上限 | 默认 0 不设上限；非负安全整数；正数完整执行该轮后仍未分胜负则防守方胜 |
| `waitInputSec` | 西游整轮输入等待秒数 | 默认 30 秒；非负有限数、可小数，显式 0 在运行时仍回退 30 秒；PC 不限时，烟雨不等收齐 |
| `duiwei` | 默认普攻是否按对位找人 | 默认 false；true 需要先 createMap，false 随机活敌人；明确合法目标仍可手动指定 |
| `jiqi` | 是否启用集气 | 默认 false；关闭时跳过行动集气和 addJp、忽略 JP 费用，初始化省略 jp/jpMax，不发集气增减消息；true 恢复结算和同步 |
| `attackDie` | 输入检测模式 | 默认 true 调用 checkOnline，允许死亡行动者提交与普攻守尸、费用延后复验；false 调用 checkPC 严格即时预检；烟雨预设 false。直接调用具名检测函数不受开关影响 |
| `defaultAttackSkill` | 默认普攻技能表ID | 默认0表示未配置，使用前必须注册；无装配普攻时读取，目标及子技能由表配置；对位普攻配置sel.target=duiwei |
| `defaultProtectSkill` | 默认保护目标规则技能表ID | 默认0表示未配置，使用前必须注册；保护效果仍由protectBuff提供 |
| `defaultFBackSkill` | 默认反击技能表ID | 默认0表示未配置，使用前必须注册；装配反击优先，示例1093的rand=0.1，必须nofback=true；读取物理/魔法fback阶段属性，不收费 |
| `protectBuff` | 保护指令附加的 Buff ID | 可省略；配置后必须已注册且 class=protect，否则保护指令不可用 |
| `allShieldBreak` | 开启破盾者自动大招 | 缺省 false；敌方最后一面盾被打破时记录实际攻击者，完整动作后自动施放其装配大招，每队每回合最多一次；无大招或无法施放则跳过 |
| `loopType` | 循环类型 | pc/yanyu/west，默认pc；setFightGlobalData省略时保留当前值，非法值在更新前报错；createFightLoop(fight)分别创建FightLoopPC/FightLoopYanYu/FightLoopWest，不自动start/run |

`protectBuff` 应为非负安全整数或显式 `undefined`（关闭）；实际使用时仍要求 Buff 已注册且为保护类。`allShieldBreak` 应为布尔值或 `undefined`，`undefined` 按 false 处理。`duiwei/jiqi` 应为布尔值，这些类型和范围由宿主保证。

`getYanyuGlobalData()` 返回独立的 `{ loopType: 'yanyu', duiwei: true, jiqi: true, attackDie: false }`，查询及修改返回对象不会改变共享配置。宿主通过 `setFightGlobalData(getYanyuGlobalData())` 应用预设，其他省略的规则保留原值。`createFightLoop(fight)`在创建时选择循环类，之后改配置不替换已创建的驱动。

## FightData：每场战斗的表格行

| 字段 | 含义 | 缺省与边界 |
| --- | --- | --- |
| `runaway` | 是否允许逃跑 | 必填布尔值；PC/西游使用普通行动，烟雨不接受逃跑输入 |
| `aSide` / `dSide` | 攻击方 / 防守方队伍表 ID | 可选，0 有效；fmud 省略对应参数时使用，其他宿主自行决定是否使用 |
| `runawayGrade` | 逃跑等级基准 | 必填有限数；概率 clamp(1-(行动者 grade-runawayGrade)/100,0,1)，执行时读取 |
| `deathPenalty` | 败方惩罚配置值 | 必填；0 不调用惩罚，含义及执行交给宿主，成功逃跑不惩罚 |
| `winRecover` | 胜方恢复配置值 | 必填，传给宿主阵营 onWin；成功逃跑不恢复，单位由宿主定义 |
| `winReward` | 胜方奖励配置值 | 必填，传给宿主阵营 onWin；成功逃跑不发奖，配置含义由宿主定义 |

```ts
import { Fight, setFightGlobalData } from '@mosnpm/tb';

// 宿主启动时设置一次。
// 先initSkills注册这两个ID，再设置全局默认技能。
setFightGlobalData({ maxTurn: 100, waitInputSec: 30, duiwei: false, defaultAttackSkill: 1098, defaultProtectSkill: 1099, defaultFBackSkill: 1093 });

// 从宿主自己的XLS/JSON表中读取行，直接传入；库不负责加载文件。
const row = { runaway: false, runawayGrade: 0, deathPenalty: 0, winRecover: 0, winReward: 0 };
const fight = new Fight(1, row, 123);
```

原来的 `FightData.maxTurn/waitInputSec/duiwei/protectBuff/allShieldBreak` 已迁到 `FightGlobalData`，不再逐场传入，也不通过 `fight.xls` 修改。公共属性默认值（怒气倍率、集气增量）仍由独立的 [FightConstData](./战斗常量.md) 管理，它们是新建属性的默认值，不是这里的公共流程规则。

构造战斗的 `fid` 与随机 `seed` 是 `new Fight(fid, data, seed)` 的参数，不是 FightData 字段。seed 默认 0，必须安全整数，内部转 uint32；同种子还需要相同初始数据、输入与规则版本，才有可复现性。

## 三种循环

| 驱动 | 输入时机 | 普通行动 | 额外行动 |
| --- | --- | --- | --- |
| FightLoopWest | 整轮收齐玩家/召唤物指令或超时 | 保护优先级与速度排序后执行 | 规则插入行动进入队列 |
| FightLoopPC | 轮到该单位再等待；NPC 自动 | 按速度逐人输入、执行、等动画 | 插入行动不再次等待普通输入、不推进 inputTurn |
| FightLoopYanYu | 不等收齐，玩家可提交即时技能 | 速度自动普攻；显式 AI 决策可替代其普通输入 | 即时技能 FIFO、动画间隙先执行；规则插入项仍进普通行动条 |

公共流程负责初始化、回合前后、行动记录、速度变化、完整 action 和结束广播。网络、鉴权、图形动画完成通知由宿主接入。

## FightInput 全部字段

| 字段 | 含义 | 规则 |
| --- | --- | --- |
| `turn` | 当前全局回合 | West/YanYu 网络入口必填并匹配；PC 可省略，提供时也检查；底层本地方法可省略 |
| `cmd` | 指令枚举 | 必填，见下表；不能替代宿主控制权鉴权 |
| `skill` | 已学技能 ID | skill 指令使用；自动大招由内部按 ultimateSkill 填写 |
| `summon` | 本人备用宠物的配置ID | summon指令必填，0有效，不是运行UID；每只宠物本场只可出战一次 |
| `target` | 明确目标的战斗 uid | dismiss必填，其他指令可省略走自动选择，0 有效；非法明确目标拒绝，不自动换人 |
| `ultimate` | 内部自动大招标记 | 缺省false；普通提交拒绝true，由破盾大招流程设置 |
| `ignoreCostCD` | 内部免技能费用和CD标记 | 缺省/false正常；true跳过HP/MP/SP/JP费用预检与扣除、CD检查与启动，不改变已有CD。不跳过是否已学、状态及目标等检查；客户端提交true一律拒绝，只供可信内部执行指令使用 |

| FightCmdEnum | 值 | 含义 |
| --- | --- | --- |
| none | 0 | 默认普攻 |
| attack | 1 | 普通攻击，可能由装配 attackSkill 替代 |
| defend | 2 | 防御 |
| skill | 3 | 施放已学技能 |
| runaway | 4 | 无目标的整队逃跑指令，PC/西游支持，按普通速度位置执行 |
| summon | 5 | 从玩家备用宠物中召唤一只，占普通行动；替换当前宠物，新宠下回合行动 |
| dismiss | 6 | 移除指定单位，普通行动；怪物可移除怪物，召唤物检查user归属，玩家不可移除 |
| cancel | 7 | 取消/重交，具体由输入窗口处理 |
| protect | 8 | 保护另一名存活队友，作为普通行动优先排序 |

当前`summon/dismiss/cancel/protect`依次为5/6/7/8，宿主与客户端需要同步枚举版本。

### 召唤宠物

提交 `{ cmd: FightCmdEnum.summon, summon: 宠物配置ID }`，仅玩家主人可用，PC/西游支持，烟雨网络入口仍仅接受skill。每次占一个普通行动，无额外费用，执行前复验主人存活、行动状态及备用资格；死亡玩家在西游收指令阶段仍可提交，行动前复活则正常执行。

`FightUnitUser.summons`为本场未使用宠物的`Map<配置ID, () => FightUnitSummon>`；原生宿主可直接注册工厂，须返回全新、存活且UID唯一的实例。XLS入口自动注册备用宠物工厂，召唤时才分配UID和创建实例。初始fightSummon可同时列在summons中，但不会注册为备用宠物。成功召唤后删除备用项，换下或移除的宠物本场不能再次出战。

有当前宠物时通过dismiss流程让其永久离场，取消它全部剩余行动并沿用原站位，包括替换死亡宠物。没有当前宠物时按主人前、左、右、后找空位，四邻满才通过Fight.random从己方全图空位选择；满图拒绝，不消耗备用项。新宠绑定主人、阵营并初始化战斗状态，本回合不插入行动队列，下回合正常收指令和行动。

入场消息为`['summon', 主人UID, 阵营0或1, 新宠getUnitMsg()]`；客户端追加单位，MUD/简报显示召唤者和宠物名称。替换时先发旧宠dismiss及行动条更新，再发summon；全部消息仍在同一完整动作内广播和检查胜负。

### 移除单位

提交 `{ cmd: FightCmdEnum.dismiss, target: uid }`，PC/西游支持，西游网络入口仍要求当前turn和宿主鉴权；烟雨网络入口仅接受skill。指令占用操作者的一次普通行动，无费用、不抽样、不受嘲讽改选。目标必须在场，0号目标有效；不指定目标或给出非法ID直接拒绝。

玩家不能被移除；怪物可移除怪物，不检查归属或阵营；召唤物通过`FightUnitSummon.user === 操作者.uid`校验主人，user由宿主创建时设置，0有效，未设置则不能被指令移除。召唤物可以属于玩家或怪物；存活和死亡的目标都能移除。提交和实际执行均校验，操作者执行时仍须存活且不被action禁止。

离场从阵营列表删除单位、取消全部剩余行动、清空其输入并解绑Buff/AI/规则监听，不触发死亡、复活、驱散或HP变化。消息为`['dismiss', 操作者UID, 离场单位UID]`，随后同步剩余行动条；客户端删除单位及其行动记录。`dismiss(unit, ctx, operator)`事件在单位移除和内部监听清理后发出；动作结束仍走公共胜负检查。仇恨和贡献榜保留历史ID，后续通过getUnitById查询不到就跳过。

每场战斗重新创建FightUnit，单位只属于一个Fight且不复用；UID按序递增、不重复，离场后也不重用该UID。

### 逃跑执行与状态限制

`runaway: true` 时可提交 `{ cmd: FightCmdEnum.runaway }`，西游网络入口仍需要当前 `turn` 和宿主鉴权。指令不需要目标，不受嘲讽改选影响；提交只校验，不消耗随机数。执行时重新校验表格开关、存活和状态，`move` 或现有状态键 `escapse` 被禁止时不能逃跑，休息等 `action` 禁止也会跳过。西游仍允许死亡受控单位提交意图，执行前复活则可以逃跑，仍死则跳过。

概率由当前 `unit.attr.grade` 与表格 `runawayGrade` 计算；等级未提供时按 0。沿用 `getRunwayRate` 的现有拼写，等级差 50 为 50%，差 100 为 0，结果截断到 0～1。通过 `Fight.randomLess` 使用战斗随机源，仅在概率介于 0 与 1 时抽样一次。

每次尝试广播 `["runaway", uid, success]`。失败消耗当前行动，继续队列，不收费、不攻击，也不设置整场逃跑标记；普通行动位仍推动一次集气。成功设置整场 `runaway = true`，通过 `setWin` 将对方设为胜方，停止后续行动；任意一方成功逃跑都不会调用双方奖惩回调。烟雨保持只接收即时技能的约定，不增加逃跑输入。

### 输入成功不代表执行仍合法

West 死亡玩家/召唤物仍收指令：轮到前可能复活。普通攻击可明确守尸，复活后攻击原人，仍死亡则按未指定目标重新选人。自动目标默认只取活人。

单位输入、PC 输入及烟雨技能输入统一调用 `Fight.checkInput`，按 `attackDie` 选择 `checkOnline` 或 `checkPC`。true 使用允许死亡输入与普攻守尸的收指令检查，费用可留到执行时复验；false 使用严格的行动者、费用、目标、CD 和状态即时预检，拒绝死亡普攻目标。PC 准备指令时也保留合法守尸目标，不自动换人；执行前复活则攻击原人，仍死亡则按未指定目标重新选人。显式调用 `checkPC/checkOnline` 仍分别遵守各自规则。烟雨还独立检查即时施法者存活、可施法及费用；大招始终使用严格检查。提交后的对象保存副本，宿主修改原对象不会改写意图。执行时再次校验。

`hintClient` 默认空实现，由宿主向单个客户端提示 CD、费用、目标与禁止行动原因；不加入战斗广播。

## 保护与行动条

保护不是绕过排序的回合前动作。它以优先级进入普通队列，客户端行动条按实际顺序显示。保护 Buff 由配置控制到期，通常 afterTurn + lastTurn=1。

每条行动记录有独立 id；同一单位可出现多次。取消追加行动或执行资格失效时，只移除对应记录，不能把该 uid 的所有机会删掉。速度仅重排剩余普通行动，已执行/正在执行的不重新入队。

## 弱点盾与自动大招

NPC 盾启用后，弱点有效命中扣 1 格，五行与兵器同时中也只扣一次。盾大于 0 时非弱点伤害减半，弱点按原伤；扣到 0 时立即眩晕，破盾期间按原伤。下一个全局回合前恢复满盾，不等轮到该单位。

最后一个敌人盾正数变 0，且该瞬间全部存活敌人都有盾并已破时，发 break 并登记实际破盾者。直接击杀未破盾的第三人不算 break，不能从“剩下的人已破”倒推出新触发。

完整 action 的反应链及胜负检查后，由实际破盾者自动施放已装配的 `ultimateSkill`，无大招或无法施放直接跳过，不转交队友、不保留机会。每队每回合一次，不因回盾取消。群体仍按技能自身配置选人，单体以最后被破盾者为目标；执行时目标已离场或死亡且不符合技能条件，沿用公共目标失效回退规则；仍按普通规则检查状态、费用和 CD。大招不消费普通行动条或输入次数；不再有选人等待、取消输入和 `ultimateReady` 状态。客户端从原动作消息批次中的 `actor: "ultimate"` 与正常技能消息依次表现。

状态归属各阵营的 `FightSide.ultimate`：每边一个回合标记、一个待放记录。Fight在完整动作结束后先取走双方记录，再按触发顺序执行；同批次双方均触发时不会按固定阵营序号改序。异常时两边都丢弃，先执行的大招结束战斗则停止另一边。新战斗绑定阵营和Loop启动均重置本场状态。

## 结果与异常

| FightResultEnum | 值 | 含义 |
| --- | --- | --- |
| ongoing | -1 | 未结束 |
| attack | 0 | 攻击方胜 |
| defend | 1 | 防守方胜/攻击方失败 |
| draw | 2 | 双方全灭平局，不能拿它索引阵营数组 |
| outoftime | 3 | 达到全局回合上限，防守方作为胜方 |

结果类型使用 `fight.result/getResult()`，胜方使用 `winSide/getWinSide()`，败方使用 `getLostSide()`。沿用当前 `setWin` 规则：平局和超时均以防守方作为胜方。结束时调用败方 `deathPenalty(value)` 和胜方 `onWin(reward, recover)`，实际恢复、奖惩和持久化由宿主实现。成功逃跑跳过全部奖惩，未结束的手动停止也不结算。驱动先关闭输入与队列、标记停止，再执行结果回调，重入 `end()` 不重复结算；回调异常按现有错误流程记录并结束。

胜负在完整动作和反应链后检查。运行异常由驱动捕获，不继续动作或回合；仅在 `result === -1` 时按 defend 结束，已有胜负、平局或超时结果均保留。`run()` 在 `finally` 中统一收尾，单位清理、奖惩和结束通知异常分别记录，不改判已有结果。宿主在结束生命周期里解除玩家 fight 状态，自己的保存/结算失败也应确保状态释放，见 [排错与维护](./排错与维护.md)。

## simpleData：早期辅助示例输入

它不是 MonsterData 的替代结构，正式表驱动建议使用 CreateMonsterSide。

| 字段 | 含义 | 当前辅助函数行为 |
| --- | --- | --- |
| `name` | 单位名称 | 必填，传入显示数据 |
| `id` | 本场 uid | 不是模板 ID，宿主保证唯一 |
| `pos` | 平面位置 | 从 0 开始，不在辅助函数内做地图上界校验 |
| `physic` | 覆盖示例物理 BaseAttack | 部分字段用 `||`，显式 0 也会被随机默认值替代；critP 用 `??` 保留 0 |
| `magic` | 覆盖示例魔法 BaseAttack | attack/defend 随机缺省，critP 保留显式 0 |
| `heal` | 覆盖示例治疗 BaseAttack | attack 缺省/0 随机 30～40，critP 和 defend 固定 0 |
| `poison` | 覆盖示例毒 BaseAttack | 合并 defaultBaseAttack，不额外随机毒攻击力 |

该辅助函数固定初始 hp/mp 各 100、上限各 100，速度随机 100～119，物理/魔法子阶段也有演示默认值。不要从它的随机默认行为推导正式模板的缺省规则。

验证：[PC](../../tests/core/test_pc.ts)、[西游输入及综合回归](../../tests/core/test_regressions.ts)、[烟雨](../../tests/core/test_yanyu.ts)、[破盾大招](../../tests/core/skill/test_ultimate.ts)。

### 执行阶段的失效目标

PC托付技能使用 `func: 'entrust'`，把当前普通行动位交给存活的其他队友，并立即按普通行动流程重新请求其输入。受托位复用原行动ID、固定在队首，不新增受托者原有行动次数以外的队列位置；例如A/C/B变为B/C/B。每次实际进入受托位会增加受托者inputTurn，按输入次数计时的Buff也会触发。原目标行动位保留，死亡、封印和输入周期效果沿用PC普通行动规则。托付的技能费用/CD由施放者支付，受托者自行选择下一条指令。网游输入不支持；详见 [技能配置](./技能配置.md)。

普通攻击（含none）和技能在执行时统一处理主目标：未指定、已dismiss离场、死亡且不符合当前技能条件，均视为未指定，走现有自动选目标流程。对位、排序、随机、嘲讽及技能目标规则保持有效，不强制随机，也不改写原提交对象。复活技能可以保留合法的死亡目标。此规则只用于根行动；连招继承、反击等固定反应目标仍遵守自身规则。

输入阶段仍拒绝非法ID、错误阵营和不允许的目标；死亡普攻输入是否允许仍由attackDie控制。Fight记录已dismiss的UID，执行时区分已离场目标和从未存在的非法ID。没有任何合法候选则无法执行，不扣费、不启动冷却；选中合法目标后正常结算。PC、西游、烟雨出队、追加行动和大招执行共用prepareActionInput处理失效主目标。

普通提交统一通过 `Fight.checkInput`，拒绝内部 `ultimate: true` 和 `ignoreCostCD: true` 标记；`checkOnline`同样拒绝免消耗标记。自动大招由内部登记的破盾者触发，设置ultimate标记并复用普通技能执行。模仿回放设置ignoreCostCD，不改写原技能表的费用/CD。可信内部执行方法（如checkPC/processUnit/executeUnit）接受ignoreCostCD，宿主不可把未经输入入口校验的客户端对象直接送入这些路径；输入入口仍不能替代宿主鉴权。验证见 [内部免消耗指令](../../tests/core/skill/test_ignore_cost_cd.ts)。
`Fight.getSideUnits(side)` 返回阵营数组的只读视图（`readonly FightUnit[]`），不复制、不冻结，单位对象本身仍可修改。需要排序或洗牌时使用 `getSideUnitsCopy(side)`；阵营成员配置通过 `FightSide.units` 修改。
