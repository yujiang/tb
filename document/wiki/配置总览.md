## 注册与装配

`setFightGlobalData` 在宿主启动时设置一次所有战斗共用的流程规则；`new Fight(fid, row, seed)` 的 `row` 为表格提供的 `FightData`，当前包含逃跑与奖惩配置。`fight.xls` 保存表格行，`fight.globalData` 读取共享规则。

`initFightConsts` 用于初始化公共默认值，应在创建基础属性前调用；省略字段保留当前值，已有属性不受之后的更新影响。具体字段和单位覆盖规则见[战斗常量](./战斗常量.md)。

先注册技能、Buff、被动与阵型，再通过 `MonsterData` 生成单位。`initSkills/initBuffs/initPassives/initMonsters/initZhens` 使用模块级共享注册表，相同 ID 的后一次注册覆盖前一次；不是每场战斗独立的表容器。测试使用独立配置 ID。

`skills: [[id, level]]` 是学习，`attackSkill/fbackSkill/supportSkill/ultimateSkill` 是装配槽，只写装配 ID 不会学习技能。怪物生成先学习，再初始化被动，再应用模板显式装配，最后绑定规则和 AI。

## ID、等级与概率

| 表达 | 含义 | 注意 |
| --- | --- | --- |
| `IdLevel` / `IdLevelArray` | `[ID, 等级]` / 列表 | 等级 0 有效，不是概率 |
| `IdRand` | `[ID, 概率]` | 虽然源码复用了 IdLevel 的元组结构，第二项仍是概率 |
| `SpeedSkill` | `[当前速度倍率, 技能ID]` | 用于 MonsterData.extraAction，技能0在出手时重新走AI |
| `IdLevelRand` | `[Buff ID, 等级, 概率]` | 常用于 addBuff/afterSelfBuff |
| `0.2` 概率 | 20% | 不要填 20；0 必须保持 0 |
| `hit: 100` | 100 命中点数 | 与概率不是同一量纲，命中公式会除以 100 |

当前技能、Buff、被动的查询把 ID 0 当作无配置；怪物模板、阵型、运行 uid、地图位置及 character 的 0 可以有效。不要把所有 ID 都按真假值处理，也不要假设所有表都支持 0。

## 缺省不是统一取零

- 禁止字段 `no...` 缺省 false：没有额外禁止。
- `attackRate/damageRate/healRate/poisonRate` 缺省 1。
- `sel.num` 缺省 1。
- 周期 Buff 的 `skillLevel` 缺省 0。
- Buff `power` 当前缺省 0；技能 `power` 缺省取技能等级。
- 自动复活比例缺省 0.2；保护默认监听优先级 500；不屈/自动复活默认 1000。
- `FightAttr` 的基础数值结构不能省略，需由宿主完整提供；技能与属性增量可以填 `{}`。

Wiki 中标注“建议范围”时，不代表注册函数已经做了统一校验。现有断言、告警与宿主数据校验各有范围，不能把注释当作验证器。

## 现有拼写和入口差异

`TargetSelectEnum.enemy`、`CareerEnum`、`rmeoveBuff`、`critPAnit/critDeepAnit`、`OverlapEnum.RELPACE_BYPOWER` 是当前接口名。先照现有名字使用；要改名时应单独迁移源码、数据、宿主与测试。

装配字段的 `0` 也存在入口差异：MonsterData 显式装配可用 0 卸下；主动技能效果中的 `fbackSkill/supportSkill`、被动初始化中的 `fbackSkill` 当前使用真值判断，会忽略 0。字典如实记录，不借文档整理修改玩法。
